# C3-2: GPC clock effect

This diagnostic keeps the C3-1 clock programmer, counter, thermal reader and
exact POST restore. Its request routing adds the existing C2 divider operation
before A and permits A directly to C, omitting B. No voltage or memory-clock
operation is added. The programmer follows MIT nouveau v6.8
`nvkm/subdev/clk/gk104.c`; its original notices remain in the controller files
and its source mapping remains in `THIRD_PARTY_NOTICES`.

The `core` benchmark remains 200 SOLID draws over 2560 by 1600. The additional
`gpc` benchmark uses the production GRADIENT_V catalogue shader and GPU API:
a 64 by 64 BGRA target, sixteen complete gradient draws in each submission,
eight completed submissions in each timed trial. The target stores 16 KiB of
colour. Each submission evaluates 65536 fragments, exactly the ABI work cap
of 2^31 at GRADIENT_V's weight of 32768; each trial evaluates 524288 fragments.
There are no textures, CPU pixel uploads, presents or timed readbacks.
The committed shader metadata reports `gprs=29` and `tls_bytes=0`, and the
assembly has four fixed-step wide integer division loops. These existing
Breenix arithmetic routines provide the shader-heavy alternative in the brief;
cache residency is not used to establish GPC dependence. The checked MIT
nouveau v6.8 LTC files `gf100.c` and `gk104.c` expose partition/slice counts but
no byte-capacity formula, so this diagnostic does not infer a GK208 L2 size
from those counts. No new external implementation is adapted.

The intended POST duration is roughly 300–800 ms, estimated from the shader
work. Timing is a measurement, with no benchmark-time refusal threshold.
Clock dependence is assessed from the retained times and independent counter,
rather than from the workload's name or this estimate.

Order: six POST core controls; POST gpc three trials; divider 540000 gpc three;
A PLL 810000 gpc three; C PLL 1307000 gpc three and core three; D exact POST
restore gpc three. Each stage records the register-derived frequency,
independent counter and temperature; temperature is checked before each trial.
The existing completion/error, 1 percent frequency/counter and 85 C stop rules
remain. The live host watcher ends the sole diagnostic at a refusal/fault or
GT710_C3_DONE. No full suite or persistent install belongs to this step.

The recording-device check compiles the production ABI with its alloc feature,
validates the actual streams and work bounds, requires ordered completed waits,
and checks the trial order. Its companion compiles the production request
mapping to check the added bounded divider target.
