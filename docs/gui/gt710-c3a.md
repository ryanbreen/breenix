# C3a: GK208 temperature observation at POST clocks

This diagnostic does not write clocks, voltage, memory timing, fan controls,
thermal alarms or calibration coefficients. It reuses the production core
benchmark: 200 SOLID shader draws at 2560x1600, 819200000 fragments, one final
WAIT. It records POST temperature before CAPS, then temperature before each
of twelve trials, then ten idle seconds with a reading after each second.
Sensor errors remain explicit null observations and never fail startup or
abort the sequence. Failed GPU completion or a valid reading at/above the
thermal stop limit ends the diagnostic. `GT710_C3A_DONE` is the normal boundary.
The host watcher stops this lane's boot there through metal-run.

## Sources and hardware interpretation

Every file below was fetched at Linux v6.8 commit
`e8f897f4afef0031fe618a8e94127a0934896aba` and its full MIT header checked.
Paths are relative to `drivers/gpu/drm/nouveau/nvkm/` in
[the pinned official tree](https://github.com/torvalds/linux/tree/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm).

- `subdev/therm/gk104.c:93-102`: selects `gf119_therm_init` and
  `g84_temp_get`; Copyright 2018 Red Hat Inc. Dispatch reference only.
- `subdev/therm/gf119.c:112-125`: calls `g84_sensor_setup` before its
  separate fan-tachometer setup; Copyright 2012 Red Hat Inc. C3a adapts
  only the sensor call, with no fan/tachometer writes.
- `subdev/therm/g84.c:29-51`: fuse offset 0x1a8 must read 1; mask
  0x20008 with 0x80008000/value 0x80000000, mask 0x2000c with
  0x80000003/value 0, wait 20 ms. `g84_temp_get` returns 0x20400
  directly as an integer in degrees Celsius. Copyright 2012 Red Hat Inc.
- `subdev/fuse/gf100.c:27-45`: temporarily set 0x22400 bit 0x800 and
  0x21000 bit 1, read 0x21100 + fuse offset, restore 0x21000 then
  0x22400 to their saved values. Copyright 2014 Martin Peres.
- `subdev/bios/therm.c:27-60,75-140`: BIT P v1 pointer at +12/v2 at
  +16; version/header/stride/count, 3-byte tag/LE16 records; stop at the
  first positive ambient-section tag 0. Core threshold tags: critical
  0x04, down-clock 0x07, fan boost 0x08, shutdown 0x32. Temperature is
  `(value & 0xff0) >> 4`, hysteresis `value & 0xf`. This parser does not
  reject version 0x24. Copyright 2012 Nouveau Community.

The checked MIT envytools `rnndb/pm/ptherm.xml:352-380` at commit
`f102b82381f3f11cee113d16374c87091db039d9` (imports the checked full MIT
grant and author list in `rnndb/copyright.xml`) describes the calibration:
0x20008 bit 31 enables the ADC and bit 15 forces an artificial temperature;
0x2000c bits 0/1 select software slope/offset and bit 31 disables calibration.
Nouveau clears all three, selecting hardware calibration. 0x20010 holds
software slope/offset, 0x20014 holds read-only hardware slope multiplier
(low 16 bits) and offset multiplier (high 16 bits), and 0x2001c holds their
base values; rnndb describes the hardware values as the bases plus the
TEMP_CAL slope/offset fuse offsets. These fields are not programmed by C3a.
The source does not require copying those values into software: 0x20400 is
the already converted output. This XML is a documentation reference only.

The available-sensor fuse value 1 is a flag, not a slope or an offset.
The G84+ path consumes the hardware's already converted/calibrated Celsius
value; nouveau performs no software calibration-coefficient programming or
BIOS slope/offset conversion in this path. C3a follows that path exactly,
without inventing fuse coefficients. It never writes fuse contents.

Every sensor-access write emits `GT710_SENSOR_WRITE` with address, before,
written, readback and retained. Both temporary fuse-access words are restored
and checked on every fuse read, including on error. Only the sensor controls
0x20008 and 0x2000c stay in place: nouveau leaves them enabled for continuous
readings, and restoring their disabled POST values would stop the sensor.
The rest of each sensor-control word is preserved. Setup/read failures are
records, not startup failures. The pure mechanism is exercised with a
recording device, including unavailable sensor and failed restoration.

## Threshold availability

The private captured board table at 0x8553 has version 0x24 and fourteen
records. Its tags are 01,49,01,49,00,47,21,26,20,22,48,3b,3c,ff.
None is 04,07,08 or 32: the table provides no critical, down-clock,
fan-boost or shutdown threshold under nouveau's thermal parser. The decoder
retains the raw records and reports an empty threshold map, not fabricated
values. The guest independently parses the down-clock entry and uses the
brief's 85 C fallback when absent or invalid.

For comparison only, nouveau's MIT `subdev/therm/temp.c:27-42`
(Copyright 2012 The Nouveau community; header checked) sets driver defaults
fan boost 90 C / hysteresis 3, down-clock 95/3, critical 105/5, shutdown
135/5 before parsing the VBIOS. These are driver defaults, not values in this
board's table, and C3a does not substitute them for the required 85 C fallback.
Raw board firmware remains private and is not committed.
