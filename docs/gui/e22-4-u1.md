## Change and checks

size, including newline, is 2,275 bytes with 20-digit u64 values. The startup case
writes it after the timed observation, on success and failure. Unreached stamps
remain 0. `startup-font-begin` separates the new worker from target creation;
`fonts-ready` now includes taskbar coverage preparation.

Check-first `a302bc21` executes the production `sessions::start` function with
passing and failing desktop/kiosk sessions. Old main compiles, then fails because
the passing start emits no phase line; the implementation passes the four paths.
The check retains the literal 300,000,000 ns deadline and result bound.

Check-first `bd6f0202` executes BWM's production font/target startup block with a
two-way barrier. Old main compiles, then fails at target creation because font
work has not started. The implementation passes: the scoped worker parses the
font and prepares LCD coverage for `Breenix` and the same clock bytes, at the
same scaled size the taskbar draws. Target creation proceeds alongside it. The
worker joins before drawing; the returned cache is the cache drawing uses.
Warm-up errors retain a diagnostic and the normal drawing path, as title
warm-up already does. Pixel/fill validation and its strict session policy stay
in their original order. No driver or kernel code changes.
