# C2d: PM enablement and nonfatal independent measurements

K1 and the coordinator's C2d brief authorize a probe-only sequence at the
current voltage: snapshot POST; measure GPC; run nine fixed core control trials without a clock write;
set 540000 kHz; snapshot/measure/three trials; restore the exact POST
registers; snapshot/measure/three trials; `GT710_C2_DONE`.
No new target frequency is selected. The fixed work remains 200 full-screen
2560x1600 SOLID shader draws (819200000 fragments) per timed SUBMIT/WAIT.
A GPU fault, failed completion, or clock request/readback failure stops the sequence.
A counter failure emits `GT710_CLOCK_MEASURED` with `status=unmeasured` and
its reason, then continues all remaining phases and trials.

The privileged `/proc/gt710-clock` writes are ordered and one-use:
`observe post`, `gpc 540000`, `restore post`. Restore uses the saved values
of 0x137000, 0x137004, 0x137100, 0x137160 and 0x1371d0, rather than deriving
an 810000 kHz plan. It switches GPC off the PLL, restores coefficients and
control with the lock poll, selects the POST source, and restores the unused
alternate path after selecting the PLL. Other source-select bits must still
match POST. Failure closes the controller for this boot.

## Sources and registers

Individually checked MIT nouveau at Linux v6.8
`e8f897f4afef0031fe618a8e94127a0934896aba`:

- `nvkm/subdev/clk/gk104.c:46-220,222-335,356-473`: read/calc/prog and source
  ordering. The snapshot includes the four engine PLL control/coefficient/
  neighbor words (indices 0,1,2,7), both shared reference PLLs at 0xe800 and
  0xe820, eight reference source/divider slots, sixteen per-domain source,
  divider and final-divider slots, the crystal strap, and C1's memory PLLs,
  reference/divider and source switch. Inactive paths are included.
- `nvkm/engine/pm/gf100.c:128-164,207-217`: GPC performance domains start at
  0x180000 and have hardware cycle counters. `pm/gk104.c` uses the inherited
  GF100 counter functions. Neither is used to reset an engine.
- `nvkm/subdev/timer/nv04.c:43-55`: stable high/low/high PTIMER sampling.
- The existing C2 plan still uses MIT `clk/pllgt215.c:31-100` and
  `bios/pll.c:81-107,142-159,352-365` for bounded VBIOS PLL limits/calculation.

Individually checked MIT envytools at
`f102b82381f3f11cee113d16374c87091db039d9`:

- `nva/nvatiming.c:171-242` measures each GPC using CTRL=0x40002, PRE_OP=0xffff
  (constant true), and the live PRE accumulator at base+0xa8. C2b uses GPC0
  at 0x180000 and differences that accumulator across a PTIMER interval.
- `rnndb/gf100_pcounter.xml:20-33,136-213,296-300` identifies PRE_OP, CTRL,
  CTR_PRE_NEXT and GPC domain placement. Each cycle contributes when the
  four-input PRE function is true; this is independent of clock-control words.
- `rnndb/bus/ptimer.xml:25-54` identifies PTIMER high/low at 0x9410/0x9400;
  `rnndb/pm/gf100_pclock.xml` identifies the clock blocks and shared CLK7.
  These XML files import the checked MIT `rnndb/copyright.xml` grant.

Before each measurement, save PMC 0x000200 and log the counter's raw POST
view. Enable only PM bit 0x10000000, then read PMC back to flush the posted
write and log both PMC and the newly accessible counter words. The bit is
identified by MIT nouveau `nvkm/engine/pm/gf100.c:175-180` (the PM fini
reset toggles exactly this bit). Its enable operation follows MIT
`nvkm/subdev/mc/nv04.c:39-46` (masked set, then readback). The chip's MC
selection is in MIT `nvkm/engine/device/base.c:1868-1902` (GK208B selects
`gk20a_mc_new`); MIT `nvkm/subdev/mc/gk20a.c:26-34` inherits
`nv04_mc_device` and `nv50_mc_init`. MIT `nvkm/subdev/mc/nv50.c:42-48`
enables all units at MC init; this probe limits that to PM only. MIT
`nvkm/engine/pm/gk104.c:172-183` inherits GF100 PM. GK208B has no PM
constructor entry in that device table, so the GF100/GK104 PM mask is the
source for this diagnostic, not a claim that nouveau registers a GK208 PM
engine there. All these files were individually fetched at the v6.8 revision
above and their full MIT headers checked. No additional PM clock-gating
write exists in this inspected PM/MC path; this step adds none.

If any counter word still has the 0xbadf PRI-error prefix, do not treat it
as state or write it back into the counter. Emit unmeasured and restore PMC.
For accessible counters, the measurement saves PRE_OP (0x180044), CTRL (0x18009c) and the PRE
accumulator (0x1800a8), halts the inherited mode, enables constant-true counting, brackets each accumulator read
with high/low/high PTIMER reads, and uses the bracket midpoint. It reports
`khz = delta_cycles * 1000000 / delta_ptimer_ns`, with the raw deltas and
bracket widths. The PTIMER interval is at least 20 ms, bounded by 100 ms of
kernel monotonic time, and total bracket width must be at most one percent
of the interval. Setup and accumulator writes are restored and read back on
success and failure. Under C2c an active inherited counter is saved power-on
state, not a refusal. The accumulator is verified while halted before restoring
the original CTRL: an active counter can immediately advance after resuming.
After counter cleanup, restore PMC to its saved value and read it back,
then log the counter view after restoring PM. The resumed CTRL and PRE_OP must match; an originally halted accumulator must
still match too. Both halted and resumed readbacks are retained.

`GT710_COUNTER` records the five registers this method reads or writes at POST:
CTRL, PRE_OP, CTR_PRE_NEXT, PTIMER low (0x9400) and high (0x9410). It also
records saved, configured, restore-halted and restored states around each
measurement. `GT710_CLOCK_WRITE` logs each raw address/value write.
The startup inventory calls the snapshot before native display/CE/GR startup;
clock initialization before it only saves the BAR and decodes VBIOS tables.
The counter register writers in this driver are confined to this sampler;
there is no startup counter setup to attribute the inherited mode to.
Clocks and PTIMER configuration are read only during measurement.
`GT710_PMC` retains `pm-post-inventory`, `pm-before`, `pm-enabled` and
`pm-restored` readbacks. Counter records also retain `before-pm-enable`,
`after-pm-enable` and `after-pm-restore`, including inaccessible values.
Only sampling errors are nonfatal; losing native resource ownership remains
a control error. Clock readback must equal its request exactly.

Original notices are retained in `c2.rs`, `c2/observe.rs`, the existing C
oracle and `THIRD_PARTY_NOTICES`. The full register POST snapshot is retained
at inventory, before native startup; each trial phase emits a fresh snapshot
and its differences from that saved POST snapshot.

## Boot and interpretation

Build userspace with `userspace/programs/build.sh`, as the metal artifact
builder does, and build x86 release with `gt710_clock_probe`. Deploy branch
tools under the branch-tools lock immediately before the diagnostic. Watch
serial live from the boot host and stop this boot at `GT710_C2_DONE`, a fault,
a refused clock operation, or a failed completion. A PRI error or other
`status=unmeasured` counter result alone is not a stop criterion. No suite or retry boot.
The clock switch or counter setup could leave the card unresponsive; recovery
uses this boot's `metal-run stop ID` through the existing boot loop.

`GT710_CLOCK_SNAPSHOT` retains address/value pairs; `GT710_CLOCK_DIFF` and
`GT710_CLOCK_DIFF_DONE` retain differences, including POST versus restore.
`GT710_CLOCK_MEASURED` reports domain, independent kHz, method, interval_ns and timing
inputs. `GT710_CLOCK_SET` and `GT710_CLOCK_SET_RAW` retain the existing
register-derived readback separately. The fifteen `GT710_BENCH` records report
actual completed work. These diagnostic records do not alone establish K1's
cross-boot repeatability requirement.
