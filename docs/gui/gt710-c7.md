# C7: production full-clock startup

K8 and K9 use C6's hardware helpers in production after native console
handoff and scheduler initialization, before userspace GPU admission. The clock probe keeps its benchmarks, command phases, script diff
scaffolding and raw diagnostic snapshots behind `gt710_clock_probe`.

Production initializes the continuous sensor, starts the source-built C4 PMU,
executes C5c's decoded RAM initialization and live-calculated intermediate
and target memx passes, then selects the GPC PLL. Targets and voltage ID come
from the highest runtime VBIOS performance level. DDR3 RAM type, reference
PLL mode 1 and sufficient current VID voltage are required; voltage is read
without programming it. The saved POST state supplies restoration targets. C5f's before/after EXEC health records and bounded isolated sticky
underflow clear remain shared. The clear allowance covers the first post-EXEC present; startup completes
that present before reporting full clocks.
EXEC's two reply words are pause nanoseconds and PMU_IN, as in MIT nouveau;
PMU_IN is not a status code. No post-sync PLL-lock check is added.

The final clock readbacks and independent GPC pre-counter must be within K8's
one-percent bounds. A failed stage stops the upward sequence and attempts each
changed domain's restore independently: the saved five GPC words through C3's
exact restore, then the two live-calculated nouveau memory downclock passes to
405000. Failed restoration is retained on serial, and startup returns to its
caller without a clock error failing the boot. A memory pass finishes its
CPU-after programming on a missing reply before attempting recovery.

The pre-admission health check reads PGRAPH status when PMC_ENABLE has the
GR bit set, following `gr/ctxctl.rs`'s accessibility model. PMU and FIFO
checks remain active before admission. A disabled GR block's PRI sentinel
is not a live PGRAPH interrupt status.

Fallback records name the failed stage, operation/check and captured input
or actual/expected values. Helper records retain PLL limits, wait registers,
RAM decode errors, mode selection and voltage-map context on failure.
`GT710_CLOCK_TARGETS` records the runtime targets before programming.
The observer's `--startup-only` mode stops a short production capture at the
clock startup record before the suite captures.

`GT710_CLOCK_STARTUP` is the compact final record: `full`, `gpc_khz`,
`gpc_counter_khz` (GPC raw / 16), `memory_khz`, `temperature_c`, and `status`.
`GT710_CLOCK_COUNTER` records each completed verification window after sampling
and cleanup, in field order: `attempt` (one-based), `khz`, `cycles`, `b0_ns`,
`b1_ns`, `interval_ns`, `bracket_ns`, `accepted`. The endpoint spans sum to
the bracket; accepted means the bracket is at most one percent of the interval.
The counter must also be within one percent of the target divided by 16.
The requested 1307000 kHz and its rounded PLL result are separate fields in
`GT710_CLOCK_GPC`. Failed startup also prints `GT710_CLOCK_FALLBACK`, including
both restore outcomes. A failed counter is recorded as `0`, rather than as a
successful clock measurement.

The kernel's `kgputherm` worker samples independently of the controller lock
and sleeps on the scheduler timer heap for 250 ms. It emits a temperature
record on a change, trip or restore. At 85 C or a failed sensor reading it latches the guard,
restores GPC's exact POST divider path and memory to 405000 through memx,
and prints `GT710_CLOCK_GUARD` with both outcomes. An unconfirmed restore
stays armed and retries once per second, including after startup fallback.
At 95 C while restoration is unconfirmed, it stops submissions and disables
PGRAPH/PFIFO, with a latched critical record. Cooling cannot rearm or
raise clocks during the same boot. Worker creation failure prevents raising
clocks. The threshold is K8's 85 C fallback because this board has no VBIOS
threshold; no fan, voltage or system-controller operation is introduced.

The kernel command-line option `gt710.clocks=post` keeps POST clocks. Pass it
with `metal-run boot --kernel-command-line gt710.clocks=post`; it travels in
the boot intent and is available before root mounting.

Check-first commit e282803e covers fallback at each stage, independent restores
after a restore error, diagnostic POST selection, exact one-percent boundaries,
and the sticky threshold at 85 C and on sensor loss. The observer's separate
check-first commit covers full-clock records, early display/clock faults and
thermal trips. The observer validates boot, code and deployed-tools identities
before following serial. Suite performance failures remain suite results.

K8 acceptance calls for one production GPU capture and one production console
capture at the final code head. Their full records and results are retained in
the private capture and the coordinator ledger; this document claims no
hardware acceptance in advance.
