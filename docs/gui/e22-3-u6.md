# E22 22.3-u6: console handback diagnostics (#2762)

At the starting head `ff4c9269`, presentation diagnostics were exported while
`SESSION` was held. The relevant production sources matched `origin/main`
`47bebbb1` byte for byte. This unit changes the GK208 driver, not the shared
runner or a case's meaning.

## Handback path

- The runner's stage releases custody at
  `libs/libbreenix/src/suite_stage.rs:1742-1745`. A pictured case also gives back
  before signaling its runner (`libs/libbreenix/src/suite.rs:679-687`).
- `libs/libbreenix/src/graphics.rs:1255-1257` issues GIVE_BACK_DISPLAY.
  `kernel/src/syscall/handlers.rs:3532-3535` routes an active GPU to
  `gpu::give_display` (`kernel/src/gpu/mod.rs:6819-6826`).
- `kernel/src/gpu/display.rs:813-823` pops the owner under the shared transition
  and calls `restore`. An already-current saved binding can return without a
  mode switch (`:876-877`). Otherwise `restore` selects the saved extent or
  kernel mode and calls `gk208::set_mode` (`:886-895`). It then binds the saved
  frame or shows/restores the kernel screen (`:897-902`). The latter restores
  terminal drawing in `kernel/src/gpu/screen.rs:435-438`.
- Process exit also reaches restoration: `gpu::owner_ended`
  (`kernel/src/gpu/mod.rs:3064`) removes the owner through `display::ended`
  (`kernel/src/gpu/display.rs:847-860`), requesting the render thread's restore.
  The restore-pending path calls the same `restore` (`:945`).
- At the old head, `kernel/src/gpu/gk208/ce/process.rs:368-394` held `SESSION`
  through `native::present` (`:385`), transition evidence, mode publication and
  scanout-hold release. `native::present` calls `present_inner`
  (`kernel/src/gpu/gk208/native.rs:852-855`). The old `present_inner:1052`
  called `presentation_trace::dump` for the reserved console resource.
  That function emitted TIMER_WAKE and the bounded presentation rows before
  returning (`presentation_trace.rs:30-48` at the old head).

## Change

`ce/process.rs:387-398` now detaches the presentation samples and wakeup counters
under `SESSION`, completes the existing transition/mode/scanout sequence, drops
the guard, and exports the detached value. An evidence-transition error still
exports the successful presentation's snapshot after dropping the guard.
Presentation failure still returns without that export.

`presentation_trace.rs:38-61` separates snapshot/reset from formatting and serial
output. The native presentation path still records its evidence at
`native.rs:1051`; its serial dump moved to its caller. Startup retains its dump
at `production.rs:186-188`, inside `with_clock_wait`'s callback, which runs with
the session owner moved out of the lock (`ce/process.rs:223-239`).

The ARM counterpart remains the shared display restoration interface with its
VirGL/SVGA drivers. No driver interface or shared ABI was added. ARM runtime
acceptance remains unbooted in E22; this unit adds no ARM interface gap.

`kernel/src/gpu` changed, so the acceptance unit needs the plan's GPU acceptance
boot in addition to its other affected suites. This unit runs no boot and edits
no Tier-1 or Tier-2 file.

## Host checks

The first commit, `8ce0a982`, adds `tests/gt710_console_trace_lock_test.py` and its
MMIO model. It runs the extracted production mode-switch body, native diagnostic
tail and trace exporter. Compilation uses `-Dwarnings`. On the old production
sources it panics with `presentation diagnostic exported under SESSION` (Rust
exit 101; Python exit 1). On the change it passes, covering both modes, failed
presentation, failed evidence transition, invalid mode, absent session and a
forced new sample between unlock and export. The detached snapshot retains its
first/tail rows; the new sample remains for the next export.

The existing session recovery check passes (one host test); the native retained
presentation check passes (six modeled cases). Their MMIO stubs were updated for
the moved diagnostic boundary; their recovery assertions remain unchanged.
