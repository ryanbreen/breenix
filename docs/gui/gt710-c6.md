# C6 combined full clocks diagnostic

K7 composes the existing C3 GPC and C5f live memory paths under
`gt710_clock_probe`. This document describes the diagnostic, not a hardware
result. The single final-head capture is reported separately to the coordinator.

After native CAPS and normal catalogue warm-up: start the PMU, run
`gk104_ram_init`, then baseline at POST with an independent GPC counter,
PLL/divider readbacks, fresh console readback, display health, temperature,
three fixed core trials and three fixed GPC trials. Memory executes the live
405000 intermediate and 900000 target with the unchanged C5f boundary
observations and clear-once safeguard. GPC then uses C3's 1307000 PLL plan,
lock poll and source switch. No other clock target is added.

At full clocks, record the independent counter (K7 expectation 81653 kHz),
memory readback (900000 kHz), fresh console, health and temperature, then
six core and six GPC trials. Run the same core workload continuously for
at least 60 seconds, sampling temperature after the first completed trial
crossing each five-second boundary. Each completed trial is retained.
The last sample is at the 60-second boundary; there is no five-second sleep
between workloads. K7's expected times are observations to compare in the
report, not benchmark-time refusal predicates.

Return restores the exact saved POST GPC words through the existing
`observe::restore` sequence and its five exact readbacks while memory is
still at 900000. C3's whole-inventory check remains for C3; C6 records the
whole snapshot but deliberately does not require the memory words to equal
POST before the memory return. The unchanged live descending intermediate
and final EXECs then return memory to 405000. Repeat console, health,
temperature and three trials of each workload, ending at `GT710_C6_DONE`.

`gt710_c6_watch.py` watches live on the boot host. It changes its GPC target
only at `GT710_C6_GPC_TARGET`, after both upclock memory EXECs; intermediate
memory measurements must still show POST GPC. It requests `metal-run stop`
on DONE, a PLL timeout, failed EXEC/completion, GPU/display/console fault,
clock evidence outside one percent, or temperature at least 85 C. Existing
kernel bounds stop an EXEC that has no reply. A watcher parse error is logged
and does not itself request power-off. The diagnostic does not run a suite.

As with C3/C5f, a clock or memory transition could leave the card unusable
until the existing boot-loop power-off. This step adds no recovery mechanism.
MIT hardware sources and original grants are retained under the C3/C5f
entries in `THIRD_PARTY_NOTICES`; C6 adds composition and observation only.
