## Implementation and choices

- `gpu_abi::screen_crc` shares u6's SCRCRC01 types and encoder with the runner,
  adding a bounded decoder and completed-observation validation. Collection
  methods, time bound, sample quorum and device programming are unchanged.
- The CRC request tag is `SCRCRCRB`: a 48-byte header, four destination/capacity
  words, three identity lengths and inline suite/case/checkpoint tokens.
  `docs/gui/scrcrc01.md` specifies the offsets. The 32-byte SCREENRB request and
  observation v2 fields retain their existing meaning.
- `read_back_impl` retains `_scanout` and the resource's reading mark across
  pixel transfer, CRC collection and output publication. The producer receives
  the same native resource and present fence as the observation record.
  Native captures require a suite boot and the staged configuration option.
  Virtual backends are refused before firmware configuration is consulted.
  <!-- claim-lint:ok: kernel/src/gpu/mod.rs read_back_impl holds _scanout and the reading mark through the CRC call and output closure. -->
- The child's selected pre-drop end observation keeps its raw CRC too. A later
  helper without a case scanout preserves the earlier pair. Native proof
  observations bypass cached readbacks so pixels and CRC share the pin.
  <!-- claim-lint:ok: libs/libbreenix/src/suite_screen.rs before_helper_drop preserves END_CRC on no-case-scanout and snapshot gates reuse with native_crc_enabled. -->
- Child records travel through a case-local length/SHA-256 queue. The parent
  checks digest, identity, stable binding and collection eligibility, then sends
  each raw record as one existing W3 diagnostic PUT after CASE. Intent pages use
  the same observer and queue from the parent.
- The diagnostic suffix is the first eight SHA-256 bytes over `case`, NUL,
  `checkpoint`, rendered as 16 lowercase hex digits. Identity grammar excludes
  NUL. Serial carries the record's byte length, SHA-256 and upload result in
  `SCREEN_CRC_UPLOAD`; CRC SCREEN fields come from that record's first stable
  sample, raster and SOR index.
- `/proc/breenix/display-crc` is root-only. It summarizes the last completed
  capture without starting another capture. It returns ENOSYS outside suite
  boots, ENODEV on virtual backends, and errno 61 before a completed native
  capture. Entries include the discarded first sample, as SCRCRC01 does.

Production requests use SCREENRB and the existing non-CRC SCREEN formatter.
The exact production line assertion remains in the 15/15 checkpoint checks.
No shared case, threshold, approval row, Tier-1 or Tier-2 file changes.

No additional external code was adapted. The existing producer uses the MIT
nouveau crc.c/crc907d.c and cl907d definitions and MIT envytools output state,
with the grants already in modeset.rs and THIRD_PARTY_NOTICES. The wire codec
move adds no hardware sequence. G5 assets and their hashes are unchanged.
