# C5d intermediate memx diagnostic

This probe-only step calculates and executes the first DDR3 transition at
405000 kHz. It does not execute the 900000 kHz target. The VBIOS is retained
at probe initialization; register inputs are read live after PMU bring-up and
RAM initialization. The three transition fields are selected as in nouveau
`ramgk104.c:1112-1154`. The live emitted operations are printed and compared
with the first script in `gt710-c5b-memx.txt`; the comparison text is never
uploaded or executed. Differences are records, not an additional refusal.

The calculator follows MIT nouveau's DDR3 calc, inherited MR bits, fractional
reference PLL calculation and ramfuc no-op/forced-write rules. The transport
uses INFO, the source-defined DMEM ownership values, source packet batching,
and EXEC. Polling the same receive ring replaces the Linux receive worker.
The source's unbounded ownership/reply waits have a two-second diagnostic
limit so a missing reply can stop this boot. The EXEC reply contains pause
nanoseconds and PMU input; it has no firmware status field. Logged status is
the transport result; PMU input is retained as a raw word.

The CPU writes from `gk104_ram_prog_0` surround EXEC. Memory PLL/source words
are read before and after it. The existing independent GPC counter is sampled,
and the userspace observer records temperature, writes a fresh console marker
and checks it through the native console readback, then runs three core and
three GPC benchmark trials. Elapsed times are measurements without a new
threshold. The brief's stop conditions apply: missing/nonzero transport result,
GPU/PMU fault, failed completion, memory more than 1% from 405000 kHz, console
mismatch or 85 C. Completion emits `GT710_C5D_DONE`.

The first memory reclock can disrupt VRAM and scanout if the sequence fails.
Recovery is the existing metal boot loop. This step calls for one diagnostic
boot, watched live and stopped at its result; effect, reversal and repeatability remain later K1 measurements.

Sources are individually checked MIT nouveau files, pinned in
[the source manifest](provenance/gt710-c5d-sources.json), with original notices
in the adapted file and `THIRD_PARTY_NOTICES`. Firmware is unchanged from C4.
The host checks compare the live result and its CPU writes with the independent
C5b model, change inherited MR/timing input, and exercise the synchronous
INFO/upload/EXEC exchange and missing-reply path using synthetic PMU rings.
