# C3b: ADC and raw slowdown state at POST clocks

C3b removed C3a's fuse-echo and availability gate in the historical probe.
K9 restores the sensor-present condition for setup and readings; the
access-enable write still need not echo. MIT nouveau v6.8
`nvkm/subdev/fuse/gf100.c:27-38` sets both access bits, reads the word,
then restores both saved words without requiring the enables to echo.
The probe retains exact restoration checks and logs the raw 0x212a8 fuse
word. K9 rejects sensor reads on fuse errors or non-1 values.

The ADC masks remain those from MIT `therm/g84.c:40-51`: set 0x20008
bit31 and clear bit15; clear 0x2000c bits31/1/0; wait 20 ms. These select
hardware calibration (MIT rnndb `pm/ptherm.xml:352-380`). Both control
words are captured at each sample, along with raw 0x20400. Sampling checks the sensor-present fuse before reading
0x20400. No software calibration coefficients
are loaded, and there is no clock, voltage, fan or thermal-alarm write.

Sources are pinned and individually MIT-header checked as recorded in
`gt710-c3a.md` and `THIRD_PARTY_NOTICES`. New raw state uses checked MIT
nouveau `therm/gk104.c:30-90` and checked MIT envytools
`rnndb/pm/ptherm.xml` at f102b82381f3f11cee113d16374c87091db039d9,
including its imported `copyright.xml` grant. Each sample includes the
following read-only raw addresses:

| Registers | Source and purpose |
|---|---|
| 0x20000, 0x20004 | rnndb:284-350, threshold/input state in CTRL_0 and protection enables in CTRL_1 |
| 0x20008, 0x2000c | g84.c:40-51, ADC / hardware calibration control |
| 0x20044, 0x20048 | rnndb:442-460, power counter and GF100+ FSRM_UNK (not the older FSRM_STATUS layout) |
| 0x20100 | g84.c:155-158, raw thermal pending IRQ state, read without acknowledgment |
| 0x20110, 0x20114, 0x20134, 0x20138 | rnndb:661-681, thermal-protect FSRM config/current FSRM/IRQ enables/offsets |
| 0x201e0, 0x201e4, 0x201e8, 0x201ec | rnndb:707-714, four GF100+ FSRM_STATUS words, including current divisor/FSRM and thermal-protect-active bit19 |
| 0x20200..0x2021c, stride4 | gk104.c:42,55,78-87, GR/video/CE engine clock-gating controls |
| 0x20288, 0x2028c | gk104.c:46-47, FECS and hub-MMU idle filters |
| 0x20414, 0x20480, 0x20484, 0x204c0, 0x204c4 | g84.c:66-80, inherited down-clock/shutdown/hysteresis/critical/fan alarm thresholds |
| 0x200 | PMC enable, also sampled by C2d |

GK104 selects polling alarms, not g84's IRQ alarm programmer
(`gk104.c:93-105`). Reading the inherited g84 alarm words does not imply
Breenix or nouveau programmed them on this card. The new snapshot does not
acknowledge IRQs or programs alarms, gating, FSRM or PMC. Unknown and
no-PRI-response values remain raw. Runtime transports decimal address/value
pairs to userspace, which emits them as `registers` in each phase/trial's
`GT710_TEMPERATURE` JSON record.

Sequence and stop boundary remain C3a: POST before CAPS, twelve unchanged
200-draw core trials with a sample before each, ten idle samples one second
apart, then `GT710_C3A_DONE`. The v24 table has no threshold tags, so the
85 C fallback remains. Failed completion, GPU fault, or temperature >=85 C
stops the diagnostic. The host watches live and invokes metal-run stop at
that boundary. One boot only; the capture is reported without a fix/retest.
