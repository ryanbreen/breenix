# C3-1: bounded GPC PLL diagnostic

K1 and the coordinator's K2 brief authorize this probe at the existing VID:
raw GPC 810000, 1080000 and 1307000 kHz, followed by the exact POST snapshot.
C3-0's perf-level-15 voltage analysis is the basis for the 1307000 ceiling;
this diagnostic has no voltage or memory reclock operation. Production boot
behavior is unchanged; the sequence is selected by `gt710_clock_probe`.

## Hardware mechanism and source audit

The source revision is Linux v6.8
`e8f897f4afef0031fe618a8e94127a0934896aba`, under
`drivers/gpu/drm/nouveau/nvkm/`. The three file headers were fetched and read
for this step. Each has the full MIT grant:

- `subdev/clk/gk104.c`, Copyright 2013 Red Hat Inc.:
  [259-280](https://github.com/torvalds/linux/blob/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm/subdev/clk/gk104.c#L259)
  obtains the PLL limits/reference and packs P/N/M;
  [356-473](https://github.com/torvalds/linux/blob/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm/subdev/clk/gk104.c#L356)
  programs the divider/PLL/source stages.
- `subdev/clk/pllgt215.c`, Copyright 2010 Red Hat Inc.:
  [31-100](https://github.com/torvalds/linux/blob/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm/subdev/clk/pllgt215.c#L31)
  selects integer coefficients with the VBIOS limits. The existing C oracle
  retains that calculation and is compared at the three requested targets.
- `subdev/bios/pll.c`, Copyright 2005-2006 Erik Waling, Copyright 2006
  Stephane Marchesin, Copyright 2007-2009 Stuart Bennett:
  [352-365](https://github.com/torvalds/linux/blob/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm/subdev/bios/pll.c#L352)
  decodes the board's v40 PLL limits.

Full grants remain in `kernel/src/gpu/gk208/c2.rs` and the C oracle;
`THIRD_PARTY_NOTICES` maps these sources to consumers.

For GPC index 0, the existing programmer selects the divider and waits,
disables PLL sync/output and enable, writes coefficients, enables, clears
lock-test bit 4, waits up to two seconds for lock bit 17, sets bit 4 and
sync bit 2, then selects PLL source bit 0 and waits. The lock poll emits
`GT710_PLL_LOCK` with its result, elapsed microseconds and control word while
bit 4 is still clear. The C3-1 r2 brief removes the post-sync bit-17
expectation: final validation retains source bit 0 and control bits 0, 2
and 4. A lock timeout leaves the PLL unselected, restores the exact POST
snapshot and returns failure. Nouveau's stage masks
exclude index 0 from final-divider programming and the alternate source
bits used by indices 7 and up. The PLL-only planner forces this route at
810000 even though C2's divider planner can reach that clock. The final
source divider must already be unity. K2's envelope and the 1% calculated
frequency tolerance are checked before programming.

## Single-boot sequence

The userspace sequence uses the existing production GPU CAPS admission,
catalogue warm-up and fixed 200-draw, 819200000-fragment core benchmark.
A final GPU WAIT completes before a clock write. Clock programming and
counter sampling hold the native CE/GR resource owner.

| Phase | Control | Core trials | Counter expectation, kHz |
|---|---|---|---:|
| POST | Snapshot and measure | 1..6 | 50625 |
| A | Own PLL, raw 810000 | 7..9 | 50625 |
| B | Own PLL, raw 1080000 | 10..12 | 67500 |
| C | Own PLL, raw 1307000 | 13..15 | 81688 |
| D | Exact POST snapshot, divider | 16..18 | 50625 |

Each control emits `GT710_CLOCK_SNAPSHOT`, differences,
`GT710_CLOCK_MEASURED`, `GT710_CLOCK_SET` and raw register readback.
Temperature follows the control and precedes each trial. A pre-control
sensor check refuses writes at 85 C or an invalid sensor value. Register
readback and the measured counter must be within 1% of their targets;
measurement failure is fatal for C3. The measured local counter frequency
is retained without multiplication: the /16 relation is the empirical K2
expectation, with its undocumented physical scale tracked in #2612.
D requires the captured clock tree to equal POST in addition to the
restore helper's readbacks of its five written registers.

The host watcher stops on lock/readback/counter errors, GPU faults,
completion failure, invalid temperature or temperature at least 85 C;
otherwise it stops on `GT710_C3_DONE`. No follow-up hardware attempt is
part of this step. A lock failure or source transition can leave the card
unusable until the existing boot loop powers it off.

The check-first commit adds coefficient/lock-order checks and stage/trial
checks before the implementations. The scoped host commands are
`python3 tests/gt710_c2_test.py` and
`python3 tests/gt710_bench_test.py`. Build with `CARGO_BUILD_JOBS=4`,
`taskpolicy -b ./userspace/programs/build.sh`, and
`taskpolicy -b cargo build --release --features gt710_clock_probe --bin qemu-uefi`.
The one diagnostic selects `--gt710-category clocks` on the pushed branch,
under the branch-tools lock; run/build/tools identity and the measured
serial records belong to the private capture and coordinator ledger.
