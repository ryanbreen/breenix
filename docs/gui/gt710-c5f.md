# C5f: observe display health around the live memory transition

This diagnostic follows K6 on the clock track. It retains C5e's PMU bring-up,
RAM initializer, baseline, live intermediate/target/return calculations,
900000/405000 kHz targets, console readback and two benchmark workloads.
It does not claim a hardware result before the diagnostic capture.

The feature-only native hooks emit `GT710_C5F_HEALTH` with raw address/value
pairs for 0x61009c, 0x616308 + head*0x800, 0x61c004 + sor*0x800, and
0x61c030 + sor*0x800. Points are `before-exec`, `after-exec`, optional
`clear-readback`, and `first-present`. The route comes from native takeover.
The health predicate is the existing native-present predicate.

At a successful target or return reply, an isolated sticky bit 4 in an
enabled repeat-mode head may be cleared once. The writes match G25's
clear-then-arm order from 0a12e2fc: mask 0x111 to 0x10, then mask 0x111 to 1.
Unrelated bits are retained; raw clear readback is logged before judging it.
There is no settle delay, modeset, vblank wait, or repeated clearing. An
unarmed/red reporting state or unhealthy channel/SOR/link refuses without a
clear. The intermediate upclock-preparation pass has no clear exception.
The downclock's live intermediate and final passes each observe their own
reply boundary. No present occurs between those two synchronous passes;
the first following present is labelled `return`.

The first present after the EXEC and the stage guard use the ordinary health
predicate with no clear path. A fresh sticky underflow is a failed step.
The deployed C5e observer already stops on `GT710_*ERROR`, native faults,
failed EXEC/completion, off-target memory beyond 1 percent, 85 C, or
`GT710_C5E_DONE`; benchmark time itself is a measurement, not a stop threshold.

The short diagnostic can fault the display or memory controller; recovery
uses the existing metal-run stop path. It runs under the branch-tools lock,
with this head as tools/build commit, and leaves these tools deployed.
No suite boot or persistent installation is part of C5f.

Register source: MIT envytools rnndb/display/g80_pdisplay.xml at
f102b82381f3f11cee113d16374c87091db039d9, with its imported MIT
rnndb/copyright.xml grant checked before adaptation. NV_HEAD_STAT defines
bit 0 ENABLE, bit 4 sticky W1C UNDERFLOWED, bit 8 MODE (0 REPEAT, 1 RED).
The new helper carries the original author list and grant, with the use
listed in THIRD_PARTY_NOTICES. K6 supplies the bounded exception, rather
than a new nouveau memory-programming success condition.

Host coverage: tests/gt710_memx_display_test.py executes the production helper
with W1C behavior, distinct head/SOR offsets, preserved unrelated bits,
non-underflow failures, a refused intermediate clear, and a fresh fault at
re-arm. Device success requires the single diagnostic's retained serial.
