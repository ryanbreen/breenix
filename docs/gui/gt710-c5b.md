`0x00001e14/0x00100002/0x002000a0` at 900000, before the source's forced DLL-reset
writes. The inherited MR1 ODT mask `0x244` is 0. The captured full fractional
word is `0x0b341000`; the target low-half update preserves its upper bits,
producing `0x0b341aab`.

Remaining register-input unknowns: **0 of the 32 C5a words**. The separate

The new host capture check failed first because the module was absent, then
passed **1 of 1** after implementation. Its address list also matches all
32 entries of C5a's `missing_registers`. This checks read selection and raw-value
preservation, not hardware behavior. The unchanged C5a generator's prior checks
were not rerun for this capture.

Local `CARGO_BUILD_JOBS=4 taskpolicy -b userspace/programs/build.sh` installed
204 binaries. The local x86 release `gt710_clock_probe` build completed in 1m25s.
Both compiler logs contain 0 warning/error lines. The boot host used its ordinary
full userspace/image recipe: userspace installed 204 binaries, the kernel built
in 150 s, Cargo jobs 4, and the full image build exited 0. Its retained userspace
and kernel logs contain 0 warning/error lines. Build/tools/code identities match
in `run.json`. The post-capture commit changes only evidence and notices;
no repeat build, test or boot was made.

The code reuses C4's MIT nouveau Linux v6.8 PMU loader and firmware unchanged.
C5a's MIT source-derived generator supplies the offline scripts; its source
revision, file hashes and full grants remain in
[the source manifest](provenance/gt710-c5a-sources.json), the generator header
and `THIRD_PARTY_NOTICES`. The new raw-read module is Breenix code using the
C5a input list, with no imported hardware sequence.
