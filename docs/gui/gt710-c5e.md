# C5e: live 900000 kHz memory target and return

K1 and K5 govern this diagnostic. The probe starts the source-built PMU,
executes `gk104_ram_init`, and measures the fixed core and GPC workloads
three times apiece at baseline. It calculates and executes the 405000 kHz
intermediate, then calculates the 900000 kHz target from fresh post-EXEC
hardware reads. It records the target script and its operation diff against
[the C5b script](gt710-c5b-memx.txt). Differences are observations, not refusals.

After target readback, temperature, independent GPC counter and a fresh
console write/readback, it measures the same workloads again. The return
follows MIT nouveau `ramgk104.c:1136-1162`: a descending intermediate config
at 405000 kHz, then the final 405000 kHz target, each recalculated live after
the preceding EXEC. The third workload group follows the return checks.
The return has two EXEC replies because the former and target configurations
differ in the transition fields; omitting the first pass would skip nouveau's
sequence. The requested target and final return replies are recorded along
with those intermediate replies.

The permitted frequency readback interval is the stage target plus/minus 1%.
An EXEC transport failure, GPU/PMU fault, failed completion, console mismatch,
or temperature at least 85 C ends the diagnostic. Benchmark times remain
measurements; they are not an added hardware success condition. The boot
observer requests `metal-run stop` on those records or `GT710_C5E_DONE`.
Parsing errors and child-process exits are logged without a stop request.

`GT710_MEMX_READ` retains the inputs actually used for calculation;
`GT710_MEMX_OP` retains the expanded script; `GT710_MEMX_DIFF_DONE` summarizes
the comparison. `GT710_C5E_MEMORY` records C1's hardware-derived memory clock
and the memory/reference PLL/source registers. `GT710_CLOCK_MEASURED` retains
the independent GPC counter with restored setup. EXEC's reply words are the
pause nanoseconds and PMU input, as documented by the MIT firmware; the
second word is not an error status.

The checked MIT envytools rnndb `gf100_pcounter.xml` describes GPC, PART and
HUB counter domains but documents no named GK208 memory-clock signal. C5e
therefore reports the independent memory counter unavailable and does not
guess a selector. [Source hashes](provenance/gt710-c5e-counter-sources.json).
The original MIT nouveau source grants remain in the adapted files and the
source list is in `THIRD_PARTY_NOTICES`.

The host calculator check compares four live passes with the independent
C5a/C5b model, including changed MR/timing input between EXECs. The observer
checks cover stage-specific frequency bounds and explicit stops. Hardware
results belong to the retained capture; this preparation makes no clock
control or performance claim.
