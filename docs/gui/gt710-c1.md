# C1 clock baseline (K1)

This diagnostic measures the POST clock tree. It performs no clock, PLL,
voltage or memory-timing write. The sensor's four allowed setup words are
restored and read back. Native display, GR and CE initialization remain the
existing driver path. C1 records a baseline; K1 requires later
frequency readback, throughput response, reversal and a second boot.

Run `metal-run boot --branch metal-gt710/clocks --gt710-category clocks`.
This selects a separate `gt710_clock_probe` release profile (`gpu-clock`),
with probe transport and no suite. The userspace probe requests native CAPS,
uploads the private bulk records and emits `GT710_C1_DONE`. The operator's
method requires watching serial on the boot host and issuing `metal-run stop
ID` at that line, or at a C1/card error. Do not run a second boot to repair
and retest this step. Acquire the branch-tools lock before deploying tools;
the capture's `toolsCommit`, build commit and kernel commit must agree.

Serial contains `GT710_CLOCK domain=... khz=... status=...`, the sensor
reading/restoration result, endpoint and upstream `GT710_PCIE` words,
`GT710_PTIMER` configuration and four `GT710_BENCH` JSON records. Each
benchmark reports the PTIMER begin/end/elapsed nanoseconds and fixed work.
The core workload is 16 draws of the existing TRIANGLE integer profile over
512 by 512 fragment rectangles: 4,194,304 fragment invocations evaluating
96-bit edge arithmetic. The CE workload is one non-overlapping, pitch-linear
64 MiB VRAM-to-VRAM copy, 16,384 bytes by 4,096 rows. Each workload runs twice.
Both intervals include command publication and polling through the existing
engine-ordered completion; allocation, mapping and input uploads precede the
interval. Submission overhead can limit clock scaling and must be considered
when comparing later steps. No suite timing threshold is changed.

The full 256 KiB PROM window (including chained PCI images and padding) is
uploaded once as `GT710_VBIOS_V1` with the raw-image length and SHA-256.
`GT710_CLOCK_C1` retains the clock words, readings, sensor reads/writes,
voltage GPIO/PWM reads and the PCIe configuration fields. Their serial
`GT710_VBIOS_BULK` / `GT710_C1_BULK` anchors authenticate the exact ASCII
records; `GT710_BULK` authenticates the containing upload. The scorer rejects
serial bodies, absent anchors, duplicate records, altered values, altered
work counts, incomplete trials and unsuccessful completions.

Decode a retained capture on the host:

```
python3 scripts/metal/gt710_clock.py --capture PRIVATE_CAPTURE --output PRIVATE_REPORT
python3 scripts/metal/gt710_clock.py --rom PRIVATE_PROM
```

The ROM decoder checks PCI image signatures, lengths and checksums, follows
BIT P and bounds table headers, base entries and subentries. Missing optional
tables are explicit; unsupported versions or malformed tables are errors.
It decodes performance v40, cstep v10, boost v11, voltage v12/v20/v30/v40/v50,
voltage-map v10/v20, thermal v10/v20, memory timing v10/v20 and memory-map
v10/v11. Unknown timing/configuration bits retain their raw bytes alongside
the documented fields. Full PROM bytes stay in private captures.

The voltage result comes from GPIO input sense plus the VBIOS polarity/VID
mapping, or the PWM divisor/duty plus the VBIOS base/range. Voltage-map
minimum/maximum ranges are preserved, including linked entries. A full
level needs more voltage only when its minimum exceeds the current reading;
a range overlapping the reading is explicitly unresolved. No speedo setup or
voltage write is performed to force a result. PCIe limits are the captured
configuration fields, not an inference from chassis BIOS settings.

## Audited sources

The files below were fetched at Linux v6.8 commit
`e8f897f4afef0031fe618a8e94127a0934896aba` and its MIT grant/SPDX declaration
read before use, under G1. Paths are relative to
`drivers/gpu/drm/nouveau/nvkm/`. Original grants/copyrights are retained in
adapted files and mapped in `THIRD_PARTY_NOTICES`.

- [`subdev/clk/gk104.c`](https://raw.githubusercontent.com/torvalds/linux/e8f897f4afef0031fe618a8e94127a0934896aba/drivers/gpu/drm/nouveau/nvkm/subdev/clk/gk104.c):46-141 reads VCOs, PLLs, dividers and the memory mux; :144-190 reads clock domains; :193-220 maps crystal, href, GPC(0), ROP(1), hubk07(2), hubk06(7), hubk01(8), PMU(12), VDEC(14). MPLL and its reference are also retained. The existing crystal-strap decoder uses `engine/device/base.c` as documented in `gt710-clock-record.md`. These frequencies come from registers.
- `subdev/therm/g84.c`:29-52 defines the fuse-backed sensor and the 20 ms setup delay. `subdev/fuse/gf100.c`:27-45 defines the two restore-only access gates. `subdev/therm/gk104.c`:90-107 selects `g84_temp_get` for this generation. Only the four setup/gate words are written; no alarm or fan register is programmed.
- `subdev/timer/nv04.c`:42-54 reads PTIMER high/low/high; `subdev/timer/regsnv04.h`:1-8 identifies TIME_0/1 (0x9400/0x9410) and the numerator/denominator readback.
- `subdev/bios/perf.c`:28-97 defines BIT P and v40 table geometry; :148-168 gives voltage ID at base+2 and PCIe speed code at base+11; :183-200 gives 14-bit MHz subentries.
- `subdev/bios/cstep.c`:28-135 defines BIT P+0x34, v10 base and extra-point layouts. `subdev/bios/boost.c`:28-157 defines BIT P+0x30 and v11 base/domain layouts.
- `subdev/bios/volt.c`:28-160 defines BIT P+0x0c (v2), GPIO/PWM selection, signed steps, ranges and VID entries. `subdev/bios/vmap.c`:28-151 defines BIT P+0x20, linked voltage limits and coefficients.
- `subdev/bios/therm.c`:25-151 defines BIT P+0x10 (v2), section tags, critical/down-clock/fan-boost/shutdown thresholds and hysteresis.
- `subdev/bios/timing.c`:28-185 defines BIT P+8 (v2), timing v10/v20, eleven register words and named packed fields. `subdev/bios/rammap.c`:28-158 defines BIT P+4, per-frequency mapping geometry and raw board configurations.
- `subdev/bios/gpio.c`:29-139 defines the DCB GPIO pointer, line, function and polarity layouts. `subdev/volt/gpio.c`:30-58 reads VID tags. `subdev/gpio/gf119.c`:65-70 reads sense bit 14. `subdev/gpio/gk104.c`:60-70 selects that implementation. `subdev/volt/gk104.c`:37-49 reads PWM voltage and :101-120 selects PWM only when the table and GPIO agree. `subdev/gpio/base.c`:95-109 applies the logical polarity. `subdev/volt/base.c`:32-49 maps VID to voltage; :80-103 resolves linked minimums.

PCIe capability ID 0x10, PCI-to-PCI bridge bus numbers, Link Capabilities
(+0x0c), Link Control/Status (+0x10), Slot Capabilities (+0x14), and Device
Capabilities (+4) follow the PCI Express capability layout. Slot power limit
is value bits 14:7 / scale 16:15; device captured slot power limit is value
25:18 / scale 27:26. The four scales are 1, 0.1, 0.01 and 0.001 watts.
Reading configuration uses the existing PCI accessors without writes.

## Host validation for C1

The check commits precede the implementation commit. The initial C1 check
failed for the absent decoder/sensor/route. The final scoped C1 run passed
6 Python checks, including 2 compiled Rust sensor/tree checks. The separate
encoder check passed 1/1, confirming the 16 full draws, triangle program,
scissor and target fields. Existing clock and bulk checks passed 4/4 each.

The isolated encoder harness initially omitted the ABI's `alloc` feature
and therefore rejected extended draw commands; it was corrected to match
the kernel's ABI feature. The benchmark encodes one validated draw and
submits it 16 times, keeping each submission below the unchanged work cap.
Its packet check uses A197's three-word scissor packet, not separate writes.

Claim checks (extensionless tools/notices were reviewed directly):

```
claim-lint: scripts/claim-lint.py --commit-msg /tmp/gt710-c1-check-message -> exit 0
claim-lint: scripts/claim-lint.py --commit-msg /tmp/gt710-c1-extra-check-message -> exit 0
claim-lint: scripts/claim-lint.py --base HEAD -> exit 0
```

The initial whole-file prose scan reported license-grant wording and older
probe comments outside the diff. The changed-hunk scan is clean. No hardware
measurement is claimed by this host-validation section; retain the one C1
boot and its decoded report privately and report its exact serial lines to
the coordinator.

The final-source x86 diagnostic release build completed with no warnings or
errors: `CARGO_BUILD_JOBS=4 taskpolicy -b cargo build --release --features
gt710_clock_probe --bin qemu-uefi`. This is a build result, not card evidence.
