# E22 22.4-u7: session cursor and canonical scene

The private session fixture writes `etc/uitest-cursor.conf` with `visible=false`.
Bwm's config module loads this option once, through `BREENIX_CONFIG_ROOT`.
Without the option it selects the visible pointer used by main. An ordinary
start does not consult the session file. A case can call `Session::connect`,
write `visible=true` to that private file, then call `start_compositor(false)`.
The persistent bwm settings parser and its result are unchanged. Drawing,
startup checks, deferred checks and shown-client analysis use the same cursor
selection. Pointer input continues through the existing route while hidden.

`uitest-app_test --canonical` paints a separate static scene through
`uitest_canonical::draw`: a header, three color swatches, a progress bar and two
checkerboard rows in a 320x200 client. It uses opaque integer rectangles with
literal geometry and RGB. It has no font, clock, seed or process-id input.
The default app still paints the generation/thread markers used by capture
cases. On a canonical client's mouse motion, it redraws the same scene and
prints the received coordinates and the resulting commit id.

The new gfx-refgen `ui-canonical` executable invokes that scene function with
the CPU reference fill operation; the guest invokes it with the GPU fill
operation in a batch. It generated the committed PNG and pixel pin on the host.
The PNG was visually inspected at its native size. No guest capture supplied
reference pixels. PROVENANCE records the generator command, source-file SHA-256s,
PNG SHA-256 and row-major canonical BGRX pixel SHA-256. The source hashes identify
the generator authored in the same commit as these outputs.

- PNG SHA-256: `72768d6a53dae659d5936b76a900bd4e4897b6ccf9e7644f91677265c0783745`.
- x86-metal pixel SHA-256: `edf9969c42ca7aecf9992c9a47a2ee058c374b521efa3184c420a1e18b90cc56`.

The `frames/cursor-excluded` and `frames/cross-target` bodies replaced pending
in check commit `0f07b35d`. Cursor exclusion moves the relative pointer onto the
client center, requires the app's motion-triggered commit in a later composed
observation, then compares the client area against its captured buffer with
exact RGB equality. The canonical case hashes a captured client and requires
its host-authored target pin. Target selection is a provenance lookup using the
runtime architecture string, with no architecture-specific case branch.
The case reports a pin gap when no row exists. ARM's canonical-scene pin and
runtime attestation remain gaps under #2770. No driver interface was added.
These guest cases have not run in this unit.
