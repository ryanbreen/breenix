## Changes and choices

- The shared runner selects the first successful backend-6 end CRC observation
  with screen_proof=on. It runs while the case owns the display, including the
  existing pre-helper-drop observation. The guest carries no approval table;
  acceptance compares phase 1 with that case's ordinary end SCREEN and its
  approved digest/native row.
- Phase 1 re-observes the baseline. Phase 2 arms point 35 for the captured
  resource, observes and requires exactly one fired-count increment. Phase 3
  observes again, requiring the same pixels/binding and a changed SOR CRC.
  DISARM_ALL precedes phase 4, which requires both CRCs and the saved output
  configuration to return. An armed-observation error still calls disarm.
- The case clock's shared atomic claim crosses fork and returns to the parent
  before another case. Point 35's monotonic boot-lifetime fired counter also
  prevents a second successful sequence across suite-sequence exec. Sequence
  failure emits an additive SCREENPERTURB error and is not retried by that
  runner. Shared CASE verdicts retain their meaning.
- Four private raw identities, `perturb-one` through `perturb-four`, give the
  existing CRC label derivation distinct upload identities. The phase text uses
  the SHA-256 case handoff; raw SCRCRC01 bytes use the existing length/digest
  queue. Parent validation precedes emission and upload. The ordinary end
  capture and optional picture are retained across the extra observations.
- Export verifies the phase upload receipts and bytes. Ordinary records stay in
  `screen-crc.json`; phases go to `screen-perturb.json`, outside the unchanged
  native approval importer. The receiver adds four label slots without changing
  the 2 MiB request or 64 MiB boot limits.
- `screen-proof-acceptance.py --profile r240` requires distinct eligible native
  console, GPU and BreenGL boots at one kernel/build/tools commit. It keeps the
  existing native resource, capture, full-suite and memory checks, and requires
  full clocks. GPU and BreenGL must report screen_proof=on on guest and host,
  match the checkpoint inventory and a nonempty approved table without extra
  pictures, and provide raw native CRC records plus the ordered phase quartet.
- Logical modes can vary within a boot. The native scorer therefore receives
  each checkpoint's verified output-configuration digest for its approved row.
  The default `arm` profile retains its companion requirements. The new wire
  grammar is admitted by the GPU/BreenGL parsers as non-counting evidence; the
  suite scorer remains self-contained in the existing metal sandbox.

The implementation uses the existing MIT-sourced CRC/dither interfaces,
attributed to nouveau cl907d.h/crc907d.c and cl917d.h/head917d.c in
THIRD_PARTY_NOTICES. No additional hardware source is adapted. No kernel,
Tier-1/Tier-2, suite case, threshold, selection or approval table changes.
ARM's driver boundary remains latched readback/host-renderer attestation;
it lacks native output CRC and point 35. Runtime acceptance and network
checkpoint-evidence launcher gaps remain under #2770 while U3 pauses ARM boots.
