# E22 22.4-u3: frame comparison

The comparison engine in `libs/libuitest/src/compare.rs` uses libpixcheck's
shared BGRX/RGBX comparison and validation. It refuses mismatched dimensions
before invoking that comparison. Exact comparison is the default; the shared
policy enforces channel tolerance, the differing-pixel cap, masks and their
reasons. One call judges the union of the declared regions in one frame. The
verdict carries the count, first differing coordinate and both canonical colors,
and the index of the region closest to that pixel, with declaration-order ties.
The caller can map the index to the schema's region name. No driver interface
or architecture-specific code was added.

The seven requested guest case bodies exercise synthetic frames, including the
50 ms comparison bound for 1280x800 frames with one changed pixel. Check-first
commit `a27836e8` adds those bodies and host checks. The isolated host harness
at that commit failed because the engine module did not yet exist. On the
implementation, the six behavioral checks pass; the host harness also links the
cost case without executing the Breenix clock syscall. The 2/1 tolerance,
at/over cap, pixel coordinates and colors, same-frame regions, and size
refusal are covered. The host-only timing of the same input was 20.068 ms on
this Mac, informational only; it is not R240 evidence.

The scoped `suite-ui-testing` release build passed for x86 and ARM64 with no
compiler warnings. Logs are in `/tmp/e22-22-4-u3/`. ARM runtime was not booted;
the existing ARM gaps tracked by #2770 remain. No boot, deployment, PR or
merge to main was performed. The acceptance unit owns the cumulative selection
and the actual R240 timing verdict.
