# C4: source-built PMU bring-up without reclocking

The corrected C4 brief replaces #2616's nonexistent INIT reply with the
firmware's two published ring descriptors. This diagnostic does not send a
PMU message, memx script, performance request or clock command.

## Sources and hardware sequence

Sources are pinned to Linux v6.8, commit
`e8f897f4afef0031fe618a8e94127a0934896aba`, under
`drivers/gpu/drm/nouveau/nvkm/subdev/`. Each listed source's MIT header was
checked before adaptation. The firmware includes remain unchanged, including
their notices, in `vendor/kepler/nouveau-pmu/`; `vendor/kepler/sources.json`
records their upstream and vendored SHA-256 and complete license headers.

- `pmu/gk208.c:30-44` selects the GK208 firmware, `gf100_pmu_reset`,
  `gf100_pmu_enabled` and `gt215_pmu_init`.
- `pmu/gf100.c:31-44`, `mc/base.c:82-102`, `mc/gk104.c:27-30` and
  `mc/nv04.c:34-57` select PMC bit `0x2000` at `0x200`: mask off,
  mask on, then read back. Other PMC bits are preserved.
- `pmu/gt215.c:202-236` inhibits interrupts on an enabled PMU, observes a
  bounded idle wait, resets, observes the scrub wait, uploads DMEM and IMEM
  with a tag per 64 code words. As upstream does, idle/scrub timeout is
  recorded without adding a refusal.
- `pmu/gt215.c:238-260` starts execution, waits up to 2000 ms independently
  for nonzero `0x10a4d0` and `0x10a4dc`, decodes base/size and enables
  interrupts. Neither descriptor gets additional base/size requirements.
- `pmu/fuc/host.fuc:134-149` publishes the rings; it sends no INIT packet.
- `pmu/base.c:94-102` delegates initialization to the selected function.
  `pmu/gk110.c:34-88` is the separate PGOB routine already used by GR
  startup, not another firmware-start handshake.
- `pmu/gt215.c:143-174` defines the pending interrupt/UAS fault reporting.
  The diagnostic reads those words between trials and stops on a fault;
  host receive/debug notifications are not treated as faults.

`pmu.rs` implements the hardware sequence behind `gt710_clock_probe`.
The existing privileged clock proc control serializes the one-shot start
with the native CE/GR owner after catalogue warm-up and before timed trials.
It emits the pre-reset state, upload sizes and SHA-256, the bounded waits' 
raw value and elapsed microseconds, and both decoded descriptors.

## Reproducibility and diagnostic boundary

`python3 scripts/build-kepler-assets --check` rebuilds through the existing
pinned cpp/envyas pipeline twice, compares the generated assets and compares
the PMU images with their committed bytes. The Python-only build verifier
also checks committed PMU hashes and manifest entries on the x86 build host.
Firmware image hashes are in `docs/gui/provenance/kepler-toolchain.sha256.json`.

After ring readiness, the existing independent GPC counter checks the POST
baseline (50625 kHz, with the previously measured counter scale). Temperature
is read before reset and each trial. Three production core trials and three
production GPC gradient trials use the existing workloads and actual fences.
There is no benchmark-time threshold. The boot stops on the first failed
completion, descriptor timeout, fault, invalid/85 C sensor reading, or at
`GT710_C4_DONE`. No GPU/console suite is part of this diagnostic.

Replacing the VBIOS PMU removes its firmware, including any firmware fan
control (`pmu/base.c:30-48`). A failed replacement can leave the card unusable
until the existing metal boot loop powers it off. The single short capture
is the measurement; this document makes no hardware success claim.
