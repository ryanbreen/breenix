## Change

`kernel/src/gpu/gk208/display_crc.rs` implements the bounded CRC collector and
`SCRCRC01` record. `modeset.rs` supplies CRC907D core encodings and active/assembly
output snapshots. `native.rs` and the retained CE/display owner connect the
collector to the hardware I/O and ordinary synchronous present recovery path.
The producer API is `gk208::display_crc::observe`; its caller must retain the
shared display observation transition spanning pixels and CRC, with the same
resource, present fence and mode. The driver checks the physical surface against
that pinned resource. Transport wiring into the checkpoint request is a later
unit, so this unit does not begin CRC capture during an ordinary boot.

The notifier uses the existing, previously unused guarded 4 KiB `dma` allocation.
A separate handle-4 descriptor is installed in the owned instance while it is
inactive. Present, retained acknowledgement and terminal notification continue
using their separate notifier page. No additional VRAM allocation is introduced.

The sequence is context DMA then SOR/RG control, fresh scoped UPDATE, collection,
then disabled output selectors, context DMA 0 and fresh scoped UPDATE. It keeps
the first written pair but discards it from stability, requires four consecutive
nonzero agreeing pairs, checks overflow and binding/configuration stability, then
waits for context completion and retains the completed notifier tail too. The
finished record includes up to 255 samples (254 after the discarded first), with
elapsed time at most 250000 us, completed disarm and no display error. Errors
attempt disarm; an arm or disarm error also invokes the existing present path.
An uncertain hardware failure remains an error rather than an eligible record.

`docs/gui/scrcrc01.md` defines the explicit 116-byte header, names, method/value
pairs and raw normalized sample triples. The record contains the sidecar's
per-checkpoint fields, without padding, and is under 4 KiB. Output values are
read from the head's active bank and compared with its assembly bank, with
aligned, sorted, unique method addresses. The later exporter supplies enclosing
run/commit metadata and converts the recorded dimensions, source ids and CRC
words to the sidecar's textual forms; it need not reconstruct samples or methods.

named in its documentation. ARM has no equivalent virtual display CRC; its
