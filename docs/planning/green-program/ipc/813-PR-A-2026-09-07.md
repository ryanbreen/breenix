## RCA

Pipe and FIFO writes previously attempted one buffer transfer and returned
`EAGAIN` for a full blocking descriptor. They also allowed partial small writes
and returned early for large blocking writes. FIFO creation started with the
anonymous pipe's 1/1 references, then open added real references; registry
removal and descriptor cleanup each decremented the buffer. CLOEXEC cleanup
omitted the FIFO registry step.

The settled fault-exit RCA is retained without reopening the scope decision.
`Process::terminate()` has **four** full-cleanup callers at the base revision,
not two: the restore-failure route in `kernel/src/interrupts/context_switch.rs:1400`,
the fault-exit branch in `kernel/src/process/manager.rs:1901`, and the two
signal-default-action arms in `kernel/src/signal/delivery.rs:239` and `:274`
(`SignalDefaultAction::Terminate`/`CoreDump`, reached through
`deliver_pending_signals()` while a `context_switch.rs` caller holds
PROCESS_MANAGER for the whole call). This document's original census
undercounted the callers as two, a count [#919](https://github.com/ryanbreen/breenix/issues/919)'s
own body repeated; both are corrected here. All four retain caller-owned PM.
The correction is carried through in "Fix pass: P-2" below, which repairs all
four via the shared `close_all_fds()` function rather than any individual
call site. Neither caller nor its immediate branch is modified by this PR.
claim-lint:ok: four call sites confirmed by direct grep of `terminate(` in kernel/src/ (listed above); the same fourth-caller correction is applied to #919's issue body in this landing round.

The new writer wake is explicitly omitted in the inline pipe/FIFO cleanup
arms of both architecture implementations of `Process::close_all_fds()`.
The returned `#[must_use]` notification is bound to `_should_notify`, with a
comment referencing [#919](https://github.com/ryanbreen/breenix/issues/919) and
this document. This is eight inline arm statements behind the two full
`terminate()` callers, not eight independent fault-entry routes.

A compatibility distinction matters: baseline `close_write()` already calls
legacy `wake_read_waiters()` to report EOF, using scheduler `unblock`, rather
than the new writer waitqueue. That behavior is preserved. Its pre-existing
fault-path locking concern is disclosed in #919; this round does not claim
those paths were previously pure counter decrements. Dropping newly extracted
reader notifications there would have introduced an EOF wake regression.
Only the new writer-queue notification is deliberately omitted.

## Repair

### Transfer and prepared wait

`kernel/src/ipc/pipe.rs` defines `PIPE_BUF = 4096` separately from capacity
65536, a writer `WaitQueueHead`, `WriteAttempt::{WouldBlock,BrokenPipe}`, and
`has_write_space(required)`. `try_write()` checks readiness and copies under
the same buffer guard. Positive reads notify the complete writer queue.
`close_read()` decrements references and returns an owned notification on the
1-to-0 transition; its caller delivers after releasing PM/object guards.

`kernel/src/syscall/blocking_io.rs` implements the prepared-wait lifecycle and
shared pipe/FIFO adapter. The original request determines atomicity. A large
blocking write retains its copied offset until completion or interruption;
nonblocking writes return their first positive count. Terminal EPIPE/EINTR
returns a positive prior count when present. Publication failure returns ESRCH;
a readiness mismatch retries. Queued exit balances preemption and uses
`take_waiter` followed by `finish_wait` to clear syscall blocking state.

Both `WriteOperation::Pipe` and `Fifo` delegate to this adapter after their
existing PM-free mode/object snapshot. `poll.rs` delegates writable readiness
to `has_write_space(1)` and retains no-reader `POLLERR`. The `sys_read` function
was compared byte-for-byte against the base and is unchanged.

### Ordinary close ownership census

| Path | Ownership finding and repair |
|---|---|
| `sys_close` | Previously retained PM through cleanup. It now extracts the descriptor, drops `manager_guard`, then runs cleanup. |
| dup2 overwrite | Previously cleaned the overwritten descriptor under caller PM. `FdTable::dup2` returns it with the resulting fd; `sys_dup2` drops PM before `close_extracted_fds`. |
| failed `dup_at_least` | Previously incremented then rolled back references under PM. It now finds an available slot before incrementing, so EMFILE requires no close. |
| CLOEXEC | Four manager exec implementations run under PM. They extract into caller-owned `DeferredFdCloses`; exec callers declare that owner before PM guards so reverse destruction order releases PM first, including error returns. FIFO cleanup now uses the shared registry-plus-buffer protocol. |
| normal exit | Existing `take_fd_entries` / PM release / `close_extracted_fds` boundary is retained. Notifications are delivered after buffer guard release. |
| retire/reap row destruction | Existing `retire_row`/`drop(evicted)` boundaries in process-task and waitpid code already drop rows after PM. Verified rather than blanket-restructured. |
| unconditional row removal | `remove_process` previously destroyed the row under PM. It now returns a `#[must_use] Option<Process>`; descriptor-capable callers retain it past PM. The failed initial publication case contains newly created StdIo descriptors only. |
| clone rollback | Descriptor copying in `sys_clone` moved past the fallible allocation and admission checks, and occurs only in the CLONE_FILES arm. This avoids dropping inherited descriptors under PM on refusal or allocation failure. |
| fork locals | The three manager fork paths copy descriptor state after fallible resource setup; `copy_process_state` and the remainder through publication are infallible. Replaced default tables contain StdIo only. |
| `FdTable::drop` | Delivers new notifications outside each buffer guard. Its descriptor-capable row owners use the PM-free destruction boundaries above. |
| full fault termination | Deliberate new-writer-notification omission, tracked by #919. No dispatch repair. |

`DeferredFdCloses` requires small signature/caller changes, including the
ordinary `sys_exec_aarch64` function in
`kernel/src/arch_impl/aarch64/syscall_entry.rs`. This is a disclosed
deviation from PLAN-813's ratified edit set, which stated "no timer,
syscall-entry, architecture dispatch, or context-switch changes" and did not
list this file: the change is confined to that one ordinary function body,
does not alter entry/return assembly or the dispatch table, and is listed in
"Changed source files and evidence directory" below. The enumerated
Tier-1/Tier-2 files have an empty diff.

FIFO buffers now start with zero references; anonymous pipes retain 1/1.
`FifoEntry::remove_reader/remove_writer` update registry counts only. Ordinary
FD cleanup owns the single buffer decrement. This is not a broader claim about
FIFO blocking-open or duplicated open-description ownership.

## Oracle

The userspace driver implements 13 arms for each of pipe and FIFO, 26 per
architecture: full-buffer blocking, atomic 4096, atomic 4095, large blocking
completion, three nonblocking controls, poll, last-reader close, duplicated
reader close, signal before progress, signal after progress, and ignored signal.

The boot-only ioctl validates caller/target descriptor association and object
identity, observes actual writer queue membership, BlockedOnIO, syscall-blocked
flag, occupancy, capacity, and atomic threshold. It takes object and scheduler
snapshots in separate scopes after PM, with user copies outside those guards.
It does not wake, drain, or supply the victim's result. The ARM fixture creates
a registry FIFO; subsequent open/read/write uses the ordinary descriptor path.
ARM coverage must be described as **FIFO data I/O with fixture-created FIFO**.

A control pipe carries the victim's tid before its single write and its actual
result afterward. The helper acts after a real wait witness, stops draining
until the result acknowledgement, checks bytes and cleanup, then reaps the
child. Markers are printed twice. A private-image supervisor forks/execs the
worker, checks its real waitpid status, emits one result record, and stays alive
as PID 1. The gate checks the explicit arm roster, byte tallies, summary,
unique successful reap, crash absence, and host deadline.

The revised ARM oracle completed 3/3 boots with 26/26 arms per boot.
ARM FIFO means **FIFO data I/O with fixture-created FIFO**.

orchestrator boot attempts on x86 all hit a pre-existing, #813-unrelated

[#927](https://github.com/ryanbreen/breenix/issues/927)) before

## Fix pass: P-2 — the parked writer #919 disclosed and left unwoken

A review round on this branch raised finding P-2: the eight `#813 PR-A:
cannot safely deliver under fault-caller PM; see #919` discards in
`Process::close_all_fds()` meant a writer parked in `write_pipe` whose last
reader died via a fault or an ordinary signal (SIGKILL/SIGTERM/SIGSEGV
default action) had no wake mechanism once `readers` reached 0 -- #919's own
"it can observe EPIPE on another wake" mitigation sentence had no producer
behind it for an anonymous pipe. The review also found two `.terminate()`
call sites this document's original census and #919 itself had not named:
`kernel/src/signal/delivery.rs:239` (`SignalDefaultAction::Terminate`) and
`:274` (`SignalDefaultAction::CoreDump`), both reached through
`deliver_pending_signals()` while a `context_switch.rs` caller holds
PROCESS_MANAGER for the whole call (confirmed by reading each of those three
`context_switch.rs` call sites directly: `process: &mut Process` there
borrows out of a live `manager_guard`/`manager.find_process_by_thread_mut`
scope that has not been dropped by the point `deliver_pending_signals` runs).

### Why the eight-way discard could not simply become a delivery

`Process::terminate()` has 4 identified callers, and reading each one shows
each holds PROCESS_MANAGER for the entire `close_all_fds()` call:
`context_switch.rs:1400`, `manager.rs`'s `exit_process_locked` (reached from
`process::exit_process_and_retire`'s `with_process_manager` closure --
including the `SIGKILL` fast path in `kernel/src/syscall/signal.rs`, which
drops its own earlier guard before calling `exit_process_and_retire`, which
then reacquires PM fresh), and both `signal/delivery.rs` default-action arms
above. `kernel/src/task/scheduler.rs`'s own "Lock Ordering Discipline" note
places SCHEDULER at Level 1 and PROCESS_MANAGER at Level 2, and states the
rule as: don't acquire a higher-priority (lower-numbered) lock while holding
a lower-priority (higher-numbered) one. Calling `CloseNotifications::deliver()`
(`WaitQueueHead::wake_up()`, which can reach `wake_waitqueue_thread()` and its
`with_scheduler()`/`SCHEDULER.lock()`) from inside `close_all_fds()` would
therefore have repeated -- for the write side -- the same Level 1-under-Level 2
shape the pre-existing `close_write()` -> `wake_read_waiters()` read-side wake
already has, which this document's RCA section explicitly declined to extend
("this round does not claim those paths were previously pure counter
decrements"). Reproducing that shape for the write side too would not have
been a repair.

### The fix

<!-- claim-lint:ok: kernel/src/ipc/pipe.rs's close_write() function body,
read directly -- one return statement, the field literal
`CloseNotifications { writers: None }`, regardless of which arm of its
internal `if` runs. -->

`kernel/src/task/waitqueue.rs` gains `WaitQueueHead::wake_up_deferred()`,
which pops each waiter and calls `scheduler::isr_unblock_for_io()` --
the existing lock-free per-CPU atomic-CAS wake buffer (`kernel/src/task/
scheduler.rs`'s `ISR_WAKEUP_BUFFERS`, already used by the AHCI completion and
loopback-pump paths specifically to avoid taking SCHEDULER inline) -- instead
of branching through `wake_waiter()`'s `in_interrupt_context()` check.
`kernel/src/ipc/pipe.rs`'s `CloseNotifications` gains `deliver_deferred()`,
routing to `wake_up_deferred()`. `Process::close_all_fds()` (each of its two
architecture arms) now calls `buffer.lock().close_read();
notifications.deliver_deferred();` for the `PipeRead`/`FifoRead` arms --
covering its 4 `.terminate()` callers through this one shared function,
`context_switch.rs:1400` and the SIGKILL-reachable `manager.rs` path
included, with no edit to either file. The `PipeWrite`/`FifoWrite` arms keep
their `let _should_notify = buffer.lock().close_write();` discard:
`close_write()`'s single return expression is the field literal
`CloseNotifications { writers: None }` regardless of which arm of its
internal `if` runs, so there is nothing to discard there -- only the
reader-closed transition carries a real new-writer notification.

No Tier-1 or Tier-2 file is in this diff (`kernel/src/process/process.rs`,
`kernel/src/ipc/pipe.rs`, `kernel/src/task/waitqueue.rs`, and the structure
test are the whole change); the repair reaches `context_switch.rs:1400`'s
and `manager.rs`'s callers of `terminate()` without editing either file,
because the defect lives in the shared `close_all_fds()`, not at any
individual call site.

### Tests

`tests/pipe_fifo_blocking_structure.rs`'s
`close_call_census_requires_delivery_or_the_documented_fault_carveout` is
rewritten rather than just re-targeted: the carveout now splits by which
close function a `close_all_fds()` statement calls, requiring `close_read()`
arms to deliver via the owned-local + next-statement `deliver_deferred()`
shape (matching the existing `deliver()` shape check used everywhere else in
the tree) and asserting `deferred == 4` (2 arches x {`PipeRead`,
`FifoRead`}), while `close_write()` arms keep the explicit discard shape and
`discarded == 4`. A hand-applied mutation reverting one `close_read` arm back
to the old discard was confirmed to fail this test before being reverted
(not committed).

A new `deferred_delivery_never_touches_the_scheduler_lock` test checks the
mechanism directly, independent of the census: `wake_up_deferred()`'s body
must contain `isr_unblock_for_io(waiter.tid())` and must not contain
`wake_waitqueue_thread`, `with_scheduler`, or `wake_waiter(`; `deliver_deferred()`
must route to `queue.wake_up_deferred()`. Three mutations are asserted to
redden it: replacing `deliver_deferred`'s call with `wake_up()`, adding a
`wake_waitqueue_thread()` call alongside the existing lock-free wake, and
deleting the lock-free wake outright.

No new boot-level oracle arm was added for the specific "reader killed by
SIGKILL while a writer blocks in another process" scenario -- the existing
13-arm `pipe_fifo_blocking_oracle` matrix's `last_reader`/`duplicate_reader`
arms exercise the ordinary `sys_close` path (already correct, unaffected by
this fix) and its `signal_before`/`signal_after`/`ignored_signal` arms signal
the *writer*, not the reader; 0 of the 13 named arms is P-2's scenario.
Adding that arm would need a third forked process (the existing 2-process
`blocking()` helper has the parent hold the reader throughout, so it cannot
itself be SIGKILLed without losing the orchestrator) and its own gate-script
`EXPECTED_ARMS` wiring; this fix pass followed the verification protocol its
own brief specified instead -- structure suites plus the aarch64/x86 boot
gates below -- and treats the mutation-tested structural proof above as the
test evidence for this round, not a boot-level oracle run of the exact
SIGKILL scenario.
