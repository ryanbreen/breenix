## Close-delivery decision

The plan's objection is real: the inherited deferred waiter delivery calls
isr_unblock_for_io, whose full-buffer thread-context branch acquires the
scheduler. The inherited Unix close also wakes readers before returning its
owned writer notification. Neither establishes the requested PM-free boundary.
Issue 936 remains open for the inherited pipe/FIFO and ISR-buffer concerns.

The candidate returns an owned pair notification for both reader EOF and
writer EPIPE. Legacy terminate and FD-table destruction enqueue the pair via
an intrusive link allocated as part of the pair. Duplicate pending closes
coalesce. Enqueueing takes no scheduler lock, allocates no storage, and uses
no fixed-capacity ISR wake buffer. Existing PM-free reclamation entry points
on both architectures drain at most 64 pairs per pass. Unprocessed pairs
remain owned by the queue. Draining clears queue membership before observing
closed flags; a concurrent later close either coalesces before that observation
or queues another notification. Object and queue locks are dropped before
scheduler delivery. Liveness depends on the existing reclamation cadence.

No Tier-1 or Tier-2 file is edited. No dispatch/interrupt implementation is
changed. The change does not settle the pipe/FIFO portion of issue 936 or
Unix endpoint last-reference ownership.
