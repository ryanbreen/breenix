The source chain in `timer960-rca-source.txt` explains the starvation window. `kernel/src/main.rs` makes the current boot context `swapper/0`, registers it as idle, and later calls the timer-wake oracle directly. `Scheduler::schedule` deliberately excludes idle from runnable requeue and selects it only after runnable queues are exhausted. The oracle opens its barrier and unparks peers one at a time; `kthread_unpark` requests rescheduling. If a timer switches to a released CPU-bound peer before the idle coordinator finishes releasing the remaining peers, that coordinator cannot resume while the released work stays runnable. The sleeper also remains runnable waiting for the remaining peers. The backstops eventually release this circular dependency. This source-derived diagnosis and the modeled partial-release interleaving explain why the final spinning count can reach eight only after a long barrier wait; no GDB observation of the exact original preemption instruction is claimed.
