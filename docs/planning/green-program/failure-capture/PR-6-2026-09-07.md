## 2. Mechanism and ordering

Seven code/test paths change:

- `docker/qemu/lib/gate-qmp-backstop.sh`: explicit per-call paths and budget;
  one QMP_DUMP line per result; stdout-only PASS entry point.
- `scripts/forensic-capture.sh`: `--output-dir DIR` and usage text. Step 4
  onward is byte-identical to the base, checked directly against `git show`.
- `scripts/trace_memory_dump.py`: detects ELF magic, requires `--kernel`
  for cores, resolves exactly `TRACE_BUFFERS` through host `nm`, extracts
  physical PT_LOAD bytes, and prints `TRACE_DECODED_EVENTS` with or without
  validation. The raw-dump input route remains available.
- `docker/qemu/run-aarch64-boot-test-strict.sh`: private UNIX QMP socket,
  frozen-snapshot precheck, QMP line in console and both facts sidecars,
  and `BREENIX_STRICT_POLL_ITERATIONS` (default 12).
- `docker/qemu/run-aarch64-service-sequence-gate.sh`: private per-profile
  socket directory, per-boot socket, and one capture-before-kill helper.
- `tests/gate_qmp_backstop_structure.rs`: nine structural/dynamic checks.
- `tests/strand_handoff_structure.rs`: update the existing literal poll-loop
  anchor to the requested override expression; retain its break and score
  assertions. The initial preflight failed at `strict-gate poll-loop anchor`
  before any boot. After this one-line repair, that suite passed 38/38.

Stopping/dumping after SIGTERM would race QEMU teardown and could lose the
socket and memory. In the strict gate, the QMP precheck uses the SAME static
`DEADLINE_SERIAL` as the post-kill `SCORE_PASS` computation. QMP runs after
the drain decision, before host-end sampling and the explicit kill; its
elapsed time is included in the host-facts interval without extending the
scored serial deadline. The compact insertion preserves the sibling drain
ratchet's 30-line lookback as well as the new QMP ordering check.

In service-sequence, 9/9 per-boot verdict kill sites route through
`ssg_kill_with_backstop`: eight non-PASS paths pass 0 and the
`green_sequence_complete` branch passes 1. Inside that helper, the first
operational decision is dump versus PASS, then the sidecar write, then the
final statement sends SIGTERM. Its `${output_dir}.qmp.txt` sidecar is beside
the serial. The unrelated tenth raw kill in `cleanup()` is deliberately
unchanged: this is a Ctrl-C/abort safety net, not a per-boot verdict, and the
per-boot socket is not reliably in scope there. Service-sequence also remains
outside the four-gate structure-preflight wiring; widening that wiring is a
separate concern.

The outer `timeout --kill-after=1 "$budget_s" bash ...` bounds the forensic
child independently of its internal Step-3 loop or the reporting clock.
Defaults: 30 seconds for capture, with a one-second TERM-to-KILL grace;
decoding receives a separate 30-second timeout and one-second grace.
`dump_ms` measures capture only, while the strict host-facts window also
includes decoding. Invalid/nonpositive integer budgets are refused so that
`timeout 0` cannot disable the bound. These are subprocess ceilings, not a
promise about an unresponsive host filesystem or scheduler.

A nonempty core is the requested wire discriminator: `capture=complete`
does not certify ELF integrity or a validation PASS. Decode errors remain
in `qmp-decode.log`, with `decoded_events=-` if no count was produced.
Missing sockets report `qmp_socket_missing`; attempts producing no nonempty
core report `qmp_timeout` (including a forensic child that failed early).
An old core is removed before an attempted capture in a reused directory.

The 2/2 converted gates bind UNIX sockets inside mode-0700 directories. On PASS, the
library's entire body is one printf: no QMP, socat, stop, or dump operation.
The socket listener itself is configured at launch even on a green boot;
"zero cost" here means no capture operation or capture wait, not a measured
claim that configuring the listener or printing a line consumes no cycles.

## 3. Address translation and decoder checks

The extractor reads `KERNEL_VIRT_BASE` from aarch64 `linker.ld` with a regex.
`boot.S`'s pre-MMU bss-zeroing subtracts that base, and `smp.rs` independently
uses the inverse flat offset. TRACE_BUFFERS is in .bss: masking the derived
base bits gives the same PA as subtracting the base, checked in the extractor.
This is neither a runtime page-table walk nor a hardcoded high-half mask.
The kernel symbol is fixed in this aarch64 ELF; no PIE resynchronization or
cross-nm/readelf/pyelftools is involved.

The parser reads the fixed ELF64 header and 56-byte program headers with
`struct.unpack`, seeks through `e_phoff`, and requires a PT_LOAD whose
file-backed physical range contains `buffer_stride() * max_cpus` bytes.
Missing ranges and truncated segment data fail loudly with the segment list.
The live core exposed a useful incompatibility in the first extractor:
QEMU 11.0.3 reports `e_ehsize=8` despite writing the full ELF64 header.
The original `e_ehsize == 64` check rejected it before decoding. The parser
now uses the actual fixed header and `e_phoff`; segment/file bounds remain
checked. The synthetic fixture carries the observed `e_ehsize=8` too.

## 4. Tests without a real QEMU boot

`bash scripts/run-structure-tests.sh gate_qmp_backstop_structure`: 9/9 PASS.
The census discovers sourced gates under `docker/qemu/**/*.sh`, with a floor
of two, and checks both outcome calls. Strict ordering uses a preceding-line
window; service ordering extracts the helper body and requires both decisions
before its final kill, separately scanning the per-boot text for bypasses
and at least eight helper call sites.

Both same-file mutation tests run the check in both directions: the unchanged
strict file is green, then moving its real kill above the QMP declaration
produces uncovered kill sites; the unchanged service helper is green, then
swapping its own kill and dump-call lines makes its ordering predicate false.
The assertions reject a mutation that stays green. These checks passed with
the mutations detected; no on-disk gate was left mutated. A separate
`bash scripts/run-structure-tests.sh gate_qmp_backstop_structure reddens`
run passed 2/2 mutation tests immediately before the code commit; output is
in `.tmp/pr6-mutations.log`.

The fake server uses separate UNIX-socket connections for capabilities plus
`stop`, `query-status`, and `dump-guest-memory`, matching the actual forensic
script. It logs epoch-millisecond command receipts and its own SIGTERM receipt.
The success test requires stop < dump < SIGTERM, sends SIGTERM immediately
after the library returns, and checks a nonempty file yields complete even
when those deliberately fake bytes fail decoding. The PASS test requires an
empty command log. The hanging dump test reaches the dump command, uses a
three-second budget, and measures return under ten seconds; missing sockets
and invalid budgets must return under two seconds. A separate 15-second
harness timeout prevents a broken library from wedging the test runner.

The 9/9 passing tests establish ordering, budget behavior, and the PASS no-traffic path against a
**fake** server. It does not prove a real QEMU protocol round-trip or genuine
ELF-core decoding; section 5 supplies that evidence. The additional decoder
fixture uses a deliberately unrelated p_vaddr, checks the p_paddr extraction,
rejects missing/truncated data, and checks raw input and mandatory --kernel.

One test run caught a fixture-isolation defect: time-based names could collide
between concurrent tests, allowing one fixture's cleanup to remove another's
command log. Its observed failure included `FileNotFoundError: commands.log`
and the hang leg seeing a complete file. Names now include an atomic per-process
sequence and use exclusive directory creation. The rerun passed 9/9.

Sibling checks: `gate_capture_drain_structure` 6/6 and
`qemu_host_lock_structure` 3/3, both through `scripts/run-structure-tests.sh`.
The corrected live gate preflight passed 58/58 suites, 842 tests. Shell syntax,
Python compilation, and `git diff --check` also passed. No cargo test was run.

## 8. Not claimed

- **Parallels has no QMP — issue #906 stays serial-only**
- No prevention or diagnosis of the #599 or #606 wedge is established.
  This gives the converted gate paths a way to preserve evidence when the
  arming condition recurs; it is not a resolution of either issue.
- No deferred offline page-table walk is implemented. Plan section 8 Q2
  explicitly defers that work; page-table walks remain outside fault paths.
- The live test intentionally stops a healthy boot early, rather than
  reproducing a genuinely wedged guest. The same kernel passed the three
  subsequent default boots. Service-sequence wiring is checked structurally across 9/9 verdict kill sites;
  this round did not run a live service-sequence battery.
- Ordering applies to the converted explicit per-boot kill statements.
  The strict gate's existing `timeout 20` process wrapper, abort traps, and
  external signals can still terminate QEMU independently, including during
  a late capture. The socket-missing/partial result remains meaningful in
  that case; this change does not promise capture survives an external kill.
- A nonempty core can be incomplete or invalid. The wire's complete field
  is the requested file-presence discriminator, not a substitute for the
  decoder's own validation verdict.
- No stronger timestamp ordering, trace history beyond resident ring depth,
  x86 QMP coverage, or warning-free upstream Rust core build is asserted.
