# 947: scaled exit-kick fixture windows

The two aarch64 boot fixtures use 6,100 ms of deliberate waiting after scaling,
down from 50,000 ms. The C4 windows are divided by ten (800 ms first progress,
300 ms no progress, 1,500 ms absolute, 4,500 ms gate). The C5 analogues are
divided by five (1,200 ms pre-delay, 1,000 ms enclosing budget, 600 ms gate,
800 ms absolute, 400 ms first progress, 200 ms no progress).

The C4 order remains no-progress < first-progress < absolute < gate; the
three frozen workers each retain their own deadline and name. The union control
continues receiving live sibling progress until its absolute ceiling. C5 keeps
no-progress < first-progress < gate < absolute, gate < enclosing < pre-delay.
An inherited anchor is therefore already exhausted, a fresh anchor allows the
frozen target to reach its own deadline, and advancing progress reaches the
gate ceiling before either enclosing or absolute ceilings.

New total-elapsed breadcrumbs include C4 spawn/join and C5 pre-delay overhead.
Named constants live inside the two fixture functions in
`kernel/src/tracing/providers/teardown.rs`. Their wait helpers, classifier, scenario entries, cleanup and verdict
checks retain the parent behavior; the wait requests use the scaled constants. The C4/C5
precedent was re-read in `522-C4-2026-09-07.md` and `522-C5-2026-09-07.md` at
base `9f79cb71969fe9b9832b1ff921e148a76170a850`; historical line numbers in
issue 947 were not used as current citations.

Diff scope: only aarch64 `boot_tests` fixture constants/comments, total-elapsed breadcrumbs and host
structure ratchets change. Production constants, the real exit-kick gate
budgets, the 60 s test-phase budget, initialization watchdog, Tier-1/Tier-2
files, gate scripts and x86 code are untouched. No beast leg: no x86 code moves.

## Structural mutations

`exit_kick_fixture_summed_budget_under_ten_seconds` parses the constants from
the actual fixture function bodies. Its sum includes the control absolute
ceiling, three first-progress plus no-progress allowances, healthy first/2
allowance, C5 delay, first-progress plus no-progress allowance and gate ceiling:
7,600 ms < 10,000 ms. It also checks ceiling order. This is a configured
fixture budget ratchet, not a total-runtime bound including scheduler overhead.

Each scenario entry was removed singly and restored. Each red exited 101 with
one failed test; its individual restored green exited 0 with one passed test.
These are host structure mutations, not mutated-kernel boots. The original
runtime assertions still distinguish union failure, the named frozen worker,
healthy completion, inherited anchoring, fresh anchoring and gate exhaustion.
