## Build warning and preflight corrections

The prior attempt stopped after a future-incompatibility warning in the pinned Rust library. The warning's producer is stdarch NEON target-feature code under the required aarch64 soft-float ABI. Merely exporting BREENIX_RUST_FORK_LIBRARY does not select the core source for this kernel's build-std invocation.

A private copy of the pinned toolchain library lives under this lane's `.tmp/rust-src/library`. `serials/586-pr3/local-core-softfloat.patch` excludes the incompatible NEON modules and dependent portable-SIMD conversions/import from soft-float builds, without a warning suppression or shared-toolchain edit. The initial incomplete local patch failed to compile; `local-core-first-build.txt` preserves that attempt. The completed patch built the kernel without warnings/errors (`continue-build.txt`, `committed-build.txt` and each mutation's `build.txt`). The kernel target JSON and ABI were unchanged. The durable toolchain fix remains tracked by existing issues 945 and 559; neither is closed by this private build adaptation. This toolchain adaptation limits reproducibility to the recorded source patch and environment; it is not a claim that the stock pinned library builds warning-free.

Reproduce the private source preparation in a fresh lane before the build:

```sh
mkdir -p .tmp/rust-src
cp -R "$(rustc --print sysroot)/lib/rustlib/src/rust/library" .tmp/rust-src/library
patch -d .tmp/rust-src/library -p1 < docs/planning/green-program/network/serials/586-pr3/local-core-softfloat.patch
```

`serials/586-pr3/toolchain.json` records the compiler identity and original/patched file hashes.

## Mutation interpretation and blocker

Permanent wake suppression leaves the reader blocked regardless of how much bounded waiting is granted. In the actual always-extend boot, four grants did not create a wake stamp or receive three bytes. Making that test green would require either changing the injection into a delayed wake or weakening the success checks. Neither was done. The requested always-extend-green outcome therefore remains blocked by the stated permanent-wake injection semantics; the executed red ratchet is a separate, successful anti-vacuity check. The broader extracted-policy mutation run also failed compilation because its fixed-signature wrapper retained unused parameters; acceptance relies on `always-extend/guard-only.txt`, which rejected the guard at runtime without compile diagnostics.

Mutation application/restoration is recorded in `serials/586-pr3/mutate.py` and `mutation-leg.sh`. Direct recording boots use `raw-boot.py`, retain full serials and SHA-256 provenance, and terminate only their owned QEMU process group. They are not represented as full boot gates. Source was restored before strict score-only calls and before gate preflight. Top-level gate transcripts begin with their revision. For nested contention cycles, archived `gate.txt` prepends the enclosing driver’s recorded revision and cycle as an explicitly archival provenance header; `gate-raw.txt` preserves the original gate output byte-for-byte. The enclosing `run.txt` carries the contemporaneous revision-bearing STARVED_LOOP_FACTS. Mutation-image runs additionally name the recorded patch and ELF hash.

The inherited `core.hooksPath` points to the shared checkout’s `.beads/hooks`. The two code commits printed a Beads export from that hook; no Beads task-tracking command was issued. Subsequent documentation commits use a per-command `core.hooksPath=/dev/null` override to prevent repeating that side effect. The shared hook/config was not edited.
