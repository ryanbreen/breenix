**codeMatchesContract = false.** This conclusion follows from the source independently of missing proof. At `registry.rs:2633`–2648 the grant function accepts no tick-clock input or starved boolean. It refuses fewer than 30 switches, then grants 50 or 100 ms based on elapsed counter time versus 75%/90% of allocated sleep. At `:3072` the caller does not require `starved`. The existing measured classifier is context delta below 30 OR counter/tick ratio above 4 (`:2652`–2655, `:2670`, `:2686`–2687).

Concrete source-derived counterexample, not an executed test: pending Ready reader, tick=200 ms, counter=200 ms, switches=30, used extensions=0. The classifier says nonstarved, yet the policy grants 100 ms. If the reader runs during that extra interval and receives three bytes, `:3364`–3365 returns Pass. Thus an initial dispatch failure can be hidden. Conversely a low-switch starved window gets zero from the current policy. Simply recording `saw_starved` does not constrain grants.

A terminal emitted `verdict=dispatch` still implies a missing wake stamp and returns Fail (`:3210`–3217, `:3331`–3345); executor `kernel/src/test_framework/executor.rs:837`–850 emits Fail and marks failure, and strict `:532`–537 rejects aggregate boot failures. However, that is weaker than refusing an extension and failing at the first measured dispatch deadline. Furthermore `:3208` gives remembered starvation precedence even when a later uncompleted window is dispatch; preserve a terminal defect verdict rather than hiding it behind earlier starvation.

The finite allocation part is sound by inspection: initial 200 ms plus at most 200 ms extra, printed bound 400 ms. This is a cap on requested sleep, not host wall time. `extensions` is accumulated milliseconds, not a number of grants (implementation doc `:31`–33); make units explicit or add a separate grant count if retaining the plan's count grammar. Normal terminal pass/fail emits the budget marker; early setup failures bypass that emitter, although executor now prints cap/bound on their Fail marker.

Tests also need correction: `tests/loopback_pump_structure.rs:4913` pins the guard without starvation. Its current always-extend test mutates a wrapper in the host fixture (`tests/fixtures/guest_budget.rs:4`–8), not the production guard. The green host suite therefore does not certify the R220 condition.
