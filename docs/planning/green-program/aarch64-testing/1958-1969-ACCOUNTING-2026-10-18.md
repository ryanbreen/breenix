# ARM64 testing process accounting and reclaim receipts

## Process left published by the PTY ioctl oracle (#1958)

`test_arm64_pty_ioctl_path` created `pty_ioctl_test` with the simple-exit ELF through `ProcessManager::create_process`. That API publishes and counts a process row; it does not admit its main thread to the scheduler. The EarlyBoot oracle temporarily replaced the row's main thread with its observing kernel thread to supply an fd table to `sys_ioctl`. It restored the original main thread and closed the fd, but neither scheduled that user thread nor removed the row. The process therefore contributed one start and no exit, even after every scheduled userspace thread finished. In the retained failed boot `20261018T190602Z-qemu`, its creation returned PID 2 and the PTY ioctl case passed; the final report counted 410 published processes and 409 exits.

The oracle now withdraws that unscheduled fixture using the PID its own creation returned (S24). It restores the main thread, defers the address-space resources, removes the ready entry and row through the existing APIs, drops the row outside the process-manager guard, and enqueues the reclaim receipt. The existing removal accounting withdraws the start; no synthetic exit is recorded. Failed fd allocation also reaches cleanup. The ioctl still requires EFAULT and an unchanged kernel sentinel. The exact row-removal, ready-removal and enqueue censuses name the new caller; they admit no wildcard.

## Completed retirement of both receipts (#1969)

An empty queue does not prove completion because the drain selects a receipt by removing it before reclaiming frames. Enqueue can also abandon a receipt on reservation failure. The enqueue API now returns its actual queueing result. The busy-CPU oracle checks that result for each of its two PIDs, and observes each PID through the existing retirement watch, which is published only after `RetireProgress::Complete`. It captures the member's completion before moving the watch to the leader.

The verdict and strict scorer require `enqueued=2:completed=2` as well as all previous criteria, including daemon retirement of the member, spinner progress, the 1,000 ms bound, cleanup and zero backstops. Scorer self-checks reject partial enqueue or completion even when a marker says `cleaned=1:PASS`. No Tier 1 or Tier 2 file changes.
