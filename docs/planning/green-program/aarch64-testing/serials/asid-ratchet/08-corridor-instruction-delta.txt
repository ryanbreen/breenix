R157/ASID-02: what the runtime ASID census costs on the corridor-reached path
==============================================================================

Method. Two builds of the SHIPPED production profile
(cargo build --release --target aarch64-breenix-kernel.json -Z build-std=core,alloc
 -Z build-std-features=compiler-builtins-mem -p kernel --bin kernel-aarch64),
differing only in whether the two `super::ttbr0::note_shadow_publish(val);` calls
are present in kernel/src/arch_impl/aarch64/percpu.rs. Each binary disassembled
with the toolchain's llvm-objdump; instructions counted per symbol.

This is a STATIC INSTRUCTION COUNT, not a cycle measurement. It does not measure
LL/SC retry under contention, cache behaviour, or the cost of the load-acquire on
a loaded machine. No cycle measurement was taken.

Symbols. The three are the corridor-reached publishers named in the ttbr0.rs
census comment: `syscall_entry.S` and `boot.S` both `bl
check_need_resched_and_switch_arm64`, which reaches `dispatch_thread_locked`
(-> set_next_ttbr0_for_thread, switch_ttbr0_if_needed) and `dispatch_idle_locked`
(-> setup_idle_return_locked).

  symbol                        without census   with census   delta
  switch_ttbr0_if_needed             20            53       33
  set_next_ttbr0_for_thread        1925          1943       18
  setup_idle_return_locked          255           294       39

The 33 instructions added to `switch_ttbr0_if_needed` cover TWO publishes (the
root into saved_process_cr3 and the 0 into next_cr3). They are, per publish: a
load-acquire of the per-CPU-initialised flag and a per-CPU read of this CPU's
kernel root (via kernel_ttbr0), an lsr/adrp/add/csel chain that selects one of
four counters, and an ldxr/add/stxr/cbnz retry loop -- there is no LSE atomic on
this target, so the increment is LL/SC. The disassembly is below.

Against the budget. CLAUDE.md budgets interrupt handlers at <1000 cycles. 33
added instructions with two uncontended LL/SC pairs is a small fraction of that
even at one instruction per cycle, and the reschedule path this sits on is not
the timer handler itself. That is an argument from an instruction count, and it
is the only measurement taken; it is stated as such rather than as a timing
result.
