# TTBR0 shadow reconciliation, slice 1b — the tenth site, and the exemption that hid it

Slice 1 (`TTBR0-SHADOW-SLICE-2026-09-04.md`, PR #795) routed 9 of the 10
aarch64 process-root install decision sites through
`kernel/src/arch_impl/aarch64/ttbr0.rs::adopt_process_ttbr0`. It left the tenth
alone and said so: `kernel/src/syscall/time.rs::ensure_current_address_space`
lives in a file CLAUDE.md lists as Tier-1 prohibited, and slice 1 had no
approval to touch it. Three of its censuses were built around that gap — they
found the site, named it on stderr, and declined to fail on it.

This slice closes the site and retires the exemption. Base: `origin/main`
`350d9fb5`. Branch: `fix/786-slice1b-time-rs-ttbr0`.

---

## 1. Why this is a Tier-1 edit, and the ruling that authorises it

CLAUDE.md, "PROHIBITED CODE SECTIONS", Tier 1: `kernel/src/syscall/time.rs`,
reason "clock_gettime precision - called in tight loops". Tier-1 files may not
be modified "without explicit user approval".

The approval, operator ruling R156, 2026-09-04, quoted verbatim:

> make tier 1 changes if necessary

It was necessary because the defect is *in* the Tier-1 file. There is no
version of "route every process-root install through the discipline" that
reaches this site from outside it: the raw `msr` block, the operand it
installs, and the decision to install at all are all inside
`ensure_current_address_space`.
claim-lint:ok: 1 of 1 unrepaired decision site lives in `kernel/src/syscall/time.rs`.

What the edit does to the file's Tier-1 properties: nothing that the Tier-1
rule is about. It adds no logging, no lock, no heap allocation, no string
formatting, and no page-table walk. `adopt_process_ttbr0` is
`#[inline(always)]` and is the same six-instruction install this block already
ran — `dsb ishst` / `msr ttbr0_el1` / `isb` / `tlbi vmalle1is` / `dsb ish` /
`isb` — minus the `nomem` option, plus two per-CPU word stores. The install
decision logic around it is byte-for-byte what `main` had, and nothing else in
the file changed.
claim-lint:ok: 1 of 1 statement added by the diff is the call to
`kernel/src/arch_impl/aarch64/ttbr0.rs`, whose body is quoted in section 1.

kept as a test that asserts about a constant nothing reads. The suite is 19

  corridor words naming another — and by the same corridor reads slice 1
  documented. Nothing here reproduces a wrong-root return to EL0 through
  `nanosleep` or the EINTR arm, and no probe in this round read `next_cr3` at
  one of those returns. The six green boots say the change did not break the
  paths the gates exercise; they do not say the defect was reachable.
  claim-lint:ok: 0 of 6 boots in
  `docs/planning/green-program/aarch64-testing/serials/slice1b/prove/strict-1.txt`
  and its five siblings carry a wrong-root observation, because none was
  instrumented for one.
* **No timing measurement was taken.** The Tier-1 reason for `time.rs` is
  clock_gettime precision in tight loops. The argument that this edit is
  timing-neutral is structural — same instruction sequence, `#[inline(always)]`
  helper, two per-CPU stores added, one compiler option dropped — and is not
  backed by a cycle count. `ensure_current_address_space` is on the
  `nanosleep`/blocking-resume path, not on the `clock_gettime` read path;
  `sys_clock_gettime` does not call it.
  claim-lint:ok: 0 of 2 call sites of `ensure_current_address_space` in
  `kernel/src/syscall/time.rs` (`:213`, `:252`) is inside `sys_clock_gettime`.
* **Dropping `nomem` constrains the compiler, not the hardware.** No
  instruction was added and nothing is claimed about what another CPU observes;
  the hardware ordering is still the `dsb ishst` before the `msr` and the
  `dsb ish; isb` after.
  claim-lint:ok: 6 of 6 instructions in the sequence are unchanged between the
  removed block in section 2 and `adopt_process_ttbr0` in
  `kernel/src/arch_impl/aarch64/ttbr0.rs`.
