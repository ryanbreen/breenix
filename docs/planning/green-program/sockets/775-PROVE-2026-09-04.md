## 4. Strand regime — the historical mutation did not reproduce; the deterministic one did

The brief named "the bare-hlt-wedge mutation." Case-a's own record
(`serials/775/case-a/README.md`) already discloses this mutation as *a race*
— 0 of 7 boots wedged in one battery, 1 of 8 counting an uncommitted boot
from a different session — because no thread in the current
`testing,external_test_bins` profile calls `sys_poll` at all (`grep -c
sys_poll serial_kernel.log` = 0 on every boot checked this round). Two
attempts at the round-7 head reproduced that exactly: both green, `stranded=0`,
`GATE: PASS`, 0 sign the wedge fired. A third attempt was interrupted by an
SSH connection drop to beast mid-boot; the orphaned QEMU process was killed
by exact PID (R84) and its boot discarded (no verdict, not counted above or
below).

Per case-a's own precedent, this section reports the **deterministic**
mutation instead — `case-a/deterministic-strand/mutation-E.patch`, 14 lines
in `Scheduler::wake_expired_timers` (`kernel/src/task/scheduler.rs`) that
drop the timer wake for any thread whose `blocked_in_syscall` flag is set,
so such a thread's saved kernel context has no waker left: a strand produced
by construction rather than raced for (3 of 3 boots below). Applied cleanly to the round-7 head
(`git apply`, 1 file, 14 insertions), rebuilt clean (0 warnings), 3 boots via
`run-x86-gate.sh 1 full`, then reverted (`git apply -R`, `git status
--porcelain` empty, rebuilt clean again — confirmed before any commit below).
