## 2. Why a Tier-1 file, and the authorization

`kernel/src/interrupts/timer_entry.asm` is one of the five Tier-1 paths. The
defect has no other home: DF is architecturally inherited across an interrupt
gate, so the only place that can clear it for this ISR is this ISR's own entry.
The one alternative repair anyone has proposed is a workaround: deleting the two `log::trace!` sites
on the from-userspace save path would stop this specimen reproducing while
leaving DF=1 leaking into the handler and the other 226 `rep`-prefixed sites
reachable in kernel context still running backwards.

Cause: the branch's own oracle commits moved
`docker/qemu/run-x86-boot-tests.sh`'s `EXPECTED_USERSPACE_EXITS` from 104 to 105
— `df_preempt_oracle` joined the RING3_SMOKE roster as one more program that

literal and the mutation leg rewriting 105 → 104. The mutation leg passing is
what keeps the re-pin from being vacuous: a `replacen` that matched 0 occurrences
would trip its own `assert_ne!` before reaching the validator, which is exactly how it
failed a moment ago. Measured after the change: 63 passed, 0 failed.

disclosed and carried.

  `docker/qemu/run-x86-boot-tests.sh` is red on main for #787 until PR #794

  Nothing in this record rests on it. The pre-fix slot's finding stands

* **No rate is claimed, and no battery was run.** Three green boots plus two
  green production boots say the oracle's deterministic reproduction is gone on
  these bytes. They do not measure how often production workloads enter a DF=1
  window, and they are far too few to bound the residual rate of the

  characterizing a ~1/300 event wants roughly 900 boots.
* **#792 and #793 are untouched.** This round changed no file that bears on
  either, and neither was measured here.
* **The ratchet is still a lexical order check, not a control-flow analysis.**
  Its own doc comment states the limit, unchanged by this round: a `cld` on a
  branch the entry can skip would satisfy it. The instruction this round added
  is the first instruction after the entry `cli`, on the entry's only path, so
  for this entry the two coincide — but the check itself did not get stronger.
* **The `/tmp` collision hazard is mitigated per-run, not fixed.**
  `docker/qemu/run-x86-boot-tests.sh` and `docker/qemu/run-boot-parallel.sh`
  still hardcode shared `/tmp` paths. 6 of 6 boots in this slot were isolated with
  `unshare -m` plus a per-clone bind mount, which makes each serial here provably
  its own; it does not help the next lane that forgets.
* **`AGENTS.md` still carries the old Tier-1 wording.** It holds a copy of the
  prohibited-sections section at its line 228 reading "Absolutely Forbidden".
  The `CLAUDE.md` commit is scoped to `CLAUDE.md`; the divergence is real and is
  named here rather than silently widened.
* **The two `log::trace!` sites on the save path are still there.** Deleting
  `kernel/src/task/process_context.rs:267` and
  `kernel/src/interrupts/context_switch.rs:642` remains worth doing on cost

  it — and remains not a #737 fix. This round did not touch them, which is why
  the anti-vacuity leg could still reach the fault.
