# Issue 927 — x86 boot_tests-only retirement cohorts

Baseline: `19427ef42612d14bb4cc4474a7dd460cdc850a03`, origin/main at session start,
including PR 933. Implementation: `ba5a3377ccaeca6ef1ff38f15d8871454ac648e7`.
Branch: `x86/927-retire-cohort-boot-tests-only`.

The cause was obsolete `testing` feature restrictions in two x86 fork helpers.
The originally reported pairing fork failed on **iteration 0**, with an explicit
feature-refusal error. Once that helper was repaired, the later ownership oracle
exposed the matching restriction in its second constructor. Both helpers now
execute their existing CoW and constructor logic in the boot_tests-only profile.
No Tier-1 or Tier-2 file changed, and no logging was added.

- `kernel/src/process/manager.rs:2213`: supplied-page-table fork performs CoW
  independently of loader profile; installation/completion are at lines 2257
  and 2260. Parent restoration at line 2236 precedes CoW error propagation at
  line 2237.
- `kernel/src/process/manager.rs:2899`: context fork likewise has its obsolete
  cfg restrictions removed. CoW is at line 2990, restoration at line 2997, and
  error propagation at line 2998. Existing child construction remains intact.

## Gate integration and diagnostic outcomes

`docker/qemu/run-x86-boot-tests-only.sh:67` reads the exact retire, exec and
tombstone literals from `docker/qemu/run-x86-boot-tests.sh`. It requires one of
each plus one retire PASS and one exec PASS, and rejects guest failure markers.
It runs structure preflight and checks both build steps for diagnostics. Its
scope is early kernel cohorts; it does not claim userspace execution.

The oracle defaults to its sole supported pipe/FIFO program, so the requested
`bash docker/qemu/run-blocking-io-oracle-gate.sh --arch x86_64` works directly.
Its arm and reaped-result criteria are unchanged. The x86 host window is 900 seconds, matching the
existing full x86 gate; ARM retains 120 seconds.

The unsuccessful intermediate attempts are retained and not counted as passes:

- **Gate integration error:** revision d2a593cd passed 65/65 structure suites,
  then its bare preflight call inherited errexit into the informational census
  checker, which intentionally returns nonzero. The corrected call uses the
  existing gates' `if ! gate_structure_preflight ...` contract. See
  [host/boot-tests-only-preflight-wiring-fail.log](serials/927/host/boot-tests-only-preflight-wiring-fail.log)
  and [saved status census](serials/927/context-refusal/first-preflight-statuses.txt).
- **Contention:** an e8e16061 preflight hit the 300-second context-restore suite
  timeout, with 64/65 green. The single retry used one concurrent suite and
  retained the 300-second per-suite bound. It passed preflight. See
  [host/boot-tests-only-contention.log](serials/927/host/boot-tests-only-contention.log)
  and [host snapshot](serials/927/host/contention.txt).
- **Insufficient host boot window:** that retry's 120-second ceiling terminated
  a progressing guest after child PID 50, before the 64-child workload completed.
  [Transcript and revision](serials/927/host-120s/boot-tests-only-120s.log); serials
  are beside it under `host-120s/`. This motivated the 900-second x86 bound.
- **Premature diagnostic interruption:** a later run was manually stopped after
  child PID 67 during the 25-second x86 quiesce window
  (`kernel/src/tracing/providers/teardown.rs:1697`). The initial stall suspicion
  was wrong. A subsequent GDB boot hit the first drain with 128 teardown entries
  and owner 1, then emitted the exact retire record. A later sample had 81 roots
  retired, no reclaim context violations, and RIP in framebuffer pixel output.
  [Drain probe](serials/927/quiesce-diagnostic/current-probe.log),
  [later snapshot](serials/927/quiesce-diagnostic/current-snapshot.log), and
  [serial](serials/927/quiesce-diagnostic/current-gdb/serial_user.txt). The original
  interrupted serial and historically named quiesce-stall logs are in the same
  directory. No second reclaim defect or disk-setup cause is claimed.
- **Second constructor refusal:** the uninterrupted 5c35eba2 gate reached the
  ownership failure described in the RCA. Its failure prompted the final
  context-helper repair, rather than a skipped oracle or changed tally.

The regression at `tests/x86_boot_tests_profile_structure.rs:123` accepts benign
GDT setup, rejects actual double-fault banners (emitter:
`kernel/src/interrupts.rs:468`), other faults, missing arms, incorrect byte
counts, failed verdicts, incomplete summaries, duplicate results and nonzero
reaped status. Reverting the crash-text distinction rejects the healthy fixture.
